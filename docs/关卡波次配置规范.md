# 关卡波次配置规范（波次工具 · JSON 契约 · 读取规范）

> 归属：数据模型与编辑工具（D）、运行期接线（A）
> 适用版本：dev
> **状态：已实现**——`util.map.LevelWaves`、`MapLibrary` 的 waves 读写、`util.editor.WaveEditorTool` / `WaveEditorLauncher`、运行期接线（`GameConfig` / `GameController` / `WaveManager`）。
> 波次文件只决定**出怪种类、数量与节奏**，**不含任何数值**（数值归属见《数值配置 JSON 化规范》§0）。
> 关联文档：`docs/接口契约与抽象类说明.md`、`docs/多关卡与运行期切图-接口规范.md`、`README.md`。

---

## 一、背景与目标

**原状局限**：每波只能「固定 N 只 + 统一出生间隔」，敌人永远是 `NormalEnemy`；波次数 / 每波数量 / 出生间隔 / 波间倒计时全是 `GameConfig` 里的**全局单份值**；`FastEnemy` / `TankEnemy` / `BossEnemy` 已有类，但无法通过配置进入波次。

**目标**：关卡负责人**不写 Java**，就能对每个关卡配置——本关共几波、每波由哪些敌人组成（类型 × 数量 × 出生密度）、每波开始前的准备时间上限；游戏按该配置出怪并判定胜负。

---

## 二、术语与总数据流

| 术语 | 含义 |
|---|---|
| 关卡 | = 一张地图（`maps/<key>/` 目录）。切换活动地图即切换关卡与波次 |
| 波（wave） | 一次「出怪 → 清场」的完整回合，关卡内 1..N 顺序推进 |
| 出怪组（group） | 波内最小出怪单元：`{ 敌人类型, 数量, 组内出生间隔 }` |
| 出生间隔 intervalMs | 组内相邻两只敌人的出生间隔（毫秒），即「密度」（频率 = 1000/intervalMs 只/秒） |
| maxPrepMs | 该波开始前的「最长允许准备时间」（准备倒计时上限） |

```
开发期（工具写仓库文件）
  util.editor.WaveEditorTool ──▶ maps/<key>/waves.json（repo：src/main/resources/maps/<key>/）
运行期（classpath 只读）
  GameConfig/GameController ── util.map.MapLibrary.readWavesFromClasspath(key) ──▶ LevelWaves
        └─▶ GameController 按当前波取 groups → 出怪队列 → WaveManager 按时间轴出怪
```

- 一个关卡「有多少波」= 该关卡 `waves.json` 中 `waves` 数组的元素个数；
- 关卡目录缺 `waves.json` → **回退 `GameConfig` 全局行为**（保持可玩，见 §3.5）。
- ⚠️ **当前 `maps/default/waves.json` 是联调用的测试数据**（9 波、首波含 Boss），**不是最终关卡设计**；波数与组合由该文件唯一决定，后续按游戏性需要调整。

## 三、JSON 契约

### 3.1 文件位置

每张地图一份：`src/main/resources/maps/<key>/waves.json`（与 `path.json`、`spots.json` 并列，同受 `util.map.MapLibrary` 管理）。

### 3.2 顶层结构与字段

```json
{
  "name": "default_waves",
  "waves": [
    {
      "id": 1,
      "maxPrepMs": 5000,
      "groups": [
        { "type": "normal_enemy", "count": 3, "intervalMs": 1000 },
        { "type": "tank_enemy",   "count": 1, "intervalMs": 2500 }
      ]
    },
    {
      "id": 2,
      "maxPrepMs": 8000,
      "groups": [
        { "type": "normal_enemy", "count": 2, "intervalMs": 1200 },
        { "type": "boss_enemy",   "count": 1, "intervalMs": 1500 }
      ]
    }
  ]
}
```

> ⚠️ 上面是**结构示意**，**不是现行 `maps/default/waves.json` 的内容**；现行波次请看文件本身。

| 路径 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 否（缺省 `"<key>_waves"`） | 关卡名，仅标识用 |
| `waves` | array | 是 | 波次列表，**数组顺序即游戏内波次顺序**；空数组 = 本关无波（不合法，见 §3.4） |
| `waves[].id` | int | 否 | 仅阅读用；**事实来源是数组下标**（第 k 项即第 k 波），不一致仅告警 |
| `waves[].maxPrepMs` | int | 否 | 该波开始前的准备倒计时上限（毫秒，≥0）。省略 → 取 `GameConfig.waveIntermissionMs` 全局默认。**第 1 波忽略本字段**（开局直接可手动开始） |
| `waves[].groups` | array | 是 | 有序出怪组，≥1 组 |
| `groups[].type` | string | 是 | 敌人 id，词汇表见 §4；未知 id 处理见 §3.5 |
| `groups[].count` | int | 是 | 本组连续出生的敌人数（≥1） |
| `groups[].intervalMs` | int | 是 | 本组内相邻两只的出生间隔（毫秒，>0）；count = 1 时也须为正（作为「接下一组的节奏」，见 §3.3） |

### 3.3 出怪时间轴语义（组间「后组节奏接力」）

以 `T = 本波开始出怪时刻`（= 上一波清场 + 准备倒计时结束 / 玩家提前开波的瞬间）为起点：

- **第 1 只**敌人于 `T` 出生；
- 此后**每一只**的出生时刻 = 上一只出生时刻 +「负责生成这一只的组的 `intervalMs`」；
- 组内按 `count` 只连续出完，随后自动进入**下一组**——跨组的空隙同样 = 后一组自身的 `intervalMs`，因此整波是一条**无缝、节奏为「当前组间隔」**的时间轴，不会因切组产生爆发点或停顿空档；
- 组序 = `groups` 数组顺序；最后一组出完 = 该波出怪完毕。

示例时间轴（`normal×3@1000` → `tank×1@2500` → `boss×1@1500`）：

| 时刻（相对 T） | 出怪 |
|---|---|
| +0 ms | normal #1 |
| +1000 ms | normal #2 |
| +2000 ms | normal #3 |
| +4500 ms（2000+2500） | tank #1 |
| +6000 ms（4500+1500） | boss #1 |

> 结论：**任何「某只敌人」出生前，上一只与它之间必然隔着 = 将要出生这只所在组的 intervalMs**。该规则同时定义组内与组间，运行时/测试可用同一条公式校验。

### 3.4 校验规则（工具保存前拦截；加载时宽松）

| 规则 | 说明 |
|---|---|
| `waves` 非空 | 每关至少 1 波 |
| `groups` 非空 | 每波至少 1 组 |
| `count` ≥ 1 | 整数 |
| `intervalMs` > 0 | 整数，毫秒 |
| `maxPrepMs` ≥ 0 | 缺省回退规则见 §3.2 |
| `type` ∈ 词汇表 | 未知 id 由工具标红禁止保存 |

### 3.5 容错与回退（运行期，不崩）

1. `maps/<key>/waves.json` 缺失 / 整体解析失败 → 回退 `GameConfig` 全局行为（`totalWaves` / `waveEnemyCount` / `waveSpawnIntervalMs` 等），并打警告；
2. 某条 wave 结构非法（缺 groups、count<1、intervalMs≤0）→ **跳过该波**并告警；
3. 某组 `type` 不在词汇表 → **跳过该组**并告警（不阻塞其他组出怪）；
4. **波数由此文件唯一决定**；加载成功后运行时不再读 `GameConfig` 的波次全局值。

## 四、敌人 id 词汇表与数值归属

`waves.json` 里**只写敌人 id**，不写任何数值。

| id（type） | 对应具体类 | AssetKey | 工具显示名 |
|---|---|---|---|
| `normal_enemy` | `model.enemy.NormalEnemy` | `NORMAL_ENEMY` | 普通敌人 |
| `fast_enemy` | `model.enemy.FastEnemy` | `FAST_ENEMY` | 快速敌人 |
| `tank_enemy` | `model.enemy.TankEnemy` | `TANK_ENEMY` | 重甲敌人 |
| `boss_enemy` | `model.enemy.BossEnemy` | `BOSS_ENEMY` | 首领敌人 |

- 四类均已接入 `GameController.spawnEnemy(typeId)`（按 id 建类，未知 id 兜底普通敌人并告警）。
- **数值归属**：HP / 速度 / 赏金与近战攻击 / 冷却全部在 `config/balance.json`（键名清单见《数值配置 JSON 化规范》§2.2），与 `waves.json` 无关——`spawnEnemy` 按 id 从 `GameConfig` / `BalanceTable` 取参构造。
- 词汇表与代码类 / `AssetKey` 同源命名（camel→snake）：新增敌人 = 三处同步（类 + `AssetKey` + 词汇表），工具由此自动出现新选项。
- **红线**：禁止在 `waves.json` 内联任何数值（防「第二套数值通道」）。

## 五、写入侧：数据模型与编辑工具

### 5.1 数据模型与仓库（`util.map`，运行期与工具共用）

- **`util.map.LevelWaves`**（仿 `MapRoute` / `TowerSpots` 模式）：
  - 结构：`name` + `List<Wave> waves`；`Wave { int id; long maxPrepMs; List<SpawnGroup> groups; }`；`SpawnGroup { String type; int count; long intervalMs; }`（附 getter/setter）；
  - JSON：`toJson()` / `fromJson(String)`（复用 `util.json.MiniJson`），输出顺序稳定、便于 diff；另提供 `loadFromClasspath(String)`（带缓存）。
- **`util.map.MapLibrary` 扩展**：
  - 常量：`WAVES_FILE = "waves.json"`；
  - 方法：`wavesFile(key)`、`readWaves(key)`（repo 优先、退回 classpath）、`writeWaves(key, LevelWaves)`、`readWavesFromClasspath(key)`。

### 5.2 编辑工具（`util.editor`，仿 `AnimEditorTool` 工程结构）

- 类：`util.editor.WaveEditorTool`（`main()` 转发嵌套 `WaveEditorApp extends Application`）+ `util.editor.WaveEditorLauncher`；
- 启动：改 `pom.xml` javafx 插件 `mainClass` 为 `com.kingdom.game.util.editor.WaveEditorTool` → `mvn javafx:run`。

**功能清单**：

| # | 功能 | 要求 |
|---|---|---|
| 1 | 关卡（地图）选择 | 读 `maps/index.json`（`MapLibrary.listMaps`）下拉选择/新建 |
| 2 | 载入/新建 | 选中即载入该关 `waves.json`（`readWaves`）；无则新建空表模板（默认 1 波、1 组 normal×1@1000） |
| 3 | 波次列表 | ListView 展示「第 k 波（id）」，支持新增/删除/整波复制/上移/下移 |
| 4 | 单波字段 | `maxPrepMs` 输入（可留空 = 跟随全局默认）；第 1 波提示「开局直接开始，本字段无效」 |
| 5 | 出怪组表格 | 每波一张组表：列 = 敌人类型（下拉，词汇表含显示名）/ 数量 / intervalMs；组行可增/删/上移/下移；行间即时提示该组预计耗时 `count×intervalMs` 与累计出怪数 |
| 6 | 时间轴预览 | 只读列表：按 §3.3 公式生成 `时刻→敌人` 序列（便于核对密度与 Boss 位置） |
| 7 | 校验 | 保存前按 §3.4 校验；错误弹窗/行标红，禁止写出 |
| 8 | 保存 | 经 `MapLibrary.writeWaves(key, waves)` 写回；另提供「另存为 JSON」 |
| 9 | 状态栏 | 当前文件路径 + 校验摘要 +「重启游戏生效」提示 |

## 六、读取侧：运行时契约

### 6.1 loader

`GameConfig` 构造时经 `MapLibrary.readWavesFromClasspath(key)` 得到 `LevelWaves`；缺失按 §3.5 回退。数据类与仓库本身即「读取规范」的实现：运行期**只读、带缓存、不抛异常**。

### 6.2 运行期接线（现状）

1. `GameState.totalWaves` 由关卡波数（`LevelWaves.waves.size()`）提供，胜利判定随之变化。**`maps/<key>/waves.json` 是波数的唯一来源**；`config/balance.json` 的 `totalWaves` 仅在波次表缺失/为空/解析失败时作兜底。
2. `GameController.spawnEnemy` 按 `SpawnGroup.type` 查词汇表建对应敌人，数值自 `config/balance.json` 取。
3. `WaveManager.beginWave(List<SpawnOrder>)` 消费出怪队列；旧签名保留为无波表时的回退路径。
4. 波间准备：下一波 `maxPrepMs` 接入 `getNextWaveCountdownMs` / `getEarlyStartBonus` 波间倒计时机制（第 1 波仍可直接开始；提前开波奖励上限沿用 `GameConfig.earlyStartRewardCap`，整局一个值）。
5. `resetGame` / 波次推进边界（第 N 波出怪完毕且清场 → 胜利）复用现逻辑，仅数据源替换。

## 七、验收标准

1. 编译通过；新增类全部落在 §5 指定包；
2. 工具能：选关卡 → 载入/新建 → 编辑波次与出怪组（增删/排序/复制/改密度）→ 时间轴预览与 §3.3 规则一致 → 保存；
3. 保存产出的 JSON 与 §3.2 结构一致；非法输入（0 只、负间隔、空组、空波、未知 type）被拦截；
4. `LevelWaves.toJson/fromJson` 往返一致；
5. 删除该关 `waves.json` 后（模拟缺失）运行期回退不崩。

## 八、分工与红线

| 角色 | 交付 |
|---|---|
| **D（交互/UI）** | §5 全部 + §6.1 loader（`LevelWaves` / `MapLibrary` 扩展 / `WaveEditorTool` / `Launcher`） |
| **A（集成）** | §6.2 接线：出怪建类、`WaveManager` 升级、`GameState.totalWaves`、倒计时联动 |
| **E（素材）** | 仅保证 §4 词汇表与 `AssetKey` / 贴图一致，不改逻辑 |

红线：
- 波次**数据与工具不感知敌人数值**（HP / 伤害等一律不进 `waves.json`）；禁止在 waves 里内联数值形成「第二套数值通道」；
- 不得新建并行「关卡 / 波次数据源」——波次表唯一来源 = `maps/<key>/waves.json`；
- 工具类遵守分包约定（数据/仓库 `util.map`、编辑器 `util.editor`、JSON 解析用 `util.json.MiniJson`），不新增第三方 JSON 库。
