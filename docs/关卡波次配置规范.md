## 一、背景与目标

**现状局限**（`controller/WaveManager.java`、`config/GameConfig.java`）：
- 每波只能"固定 N 只 + 统一出生间隔"，敌人永远是 `NormalEnemy`；
- 波次数/每波数量/出生间隔/波间倒计时全是 `GameConfig` 里的**全局单份值**（`totalWaves/waveEnemyCount/waveSpawnIntervalMs/waveIntermissionMs`）；
- FastEnemy/TankEnemy/BossEnemy 已有类，但无法通过配置进入波次。

**目标**：关卡负责人/玩法方**不写 Java**，就能对每个关卡配置——本关共几波、每波由哪些敌人组成（类型×数量×出生密度）、每波开始前的准备时间上限；游戏按该配置出怪并判定胜负。

## 二、术语与总数据流

| 术语 | 含义 |
|---|---|
| 关卡 | = 一张地图（`maps/<key>/` 目录）。切换活动地图即切换关卡与波次 |
| 波（wave） | 一次"出怪 → 清场"的完整回合，关卡内 1..N 顺序推进 |
| 出怪组（group） | 波内最小出怪单元：`{ 敌人类型, 数量, 组内出生间隔 }` |
| 出生间隔 intervalMs | 组内相邻两只敌人的出生间隔（毫秒），即"密度"（频率 = 1000/intervalMs 只/秒） |
| maxPrepMs | 该波开始前的"最长允许准备时间"（准备倒计时上限） |

```
开发期（D 工具写仓库文件）
  util.editor.WaveEditorTool ──▶ maps/<key>/waves.json（repo：src/main/resources/maps/<key>/）
运行期（classpath 只读）
  GameConfig/GameController ── util.map.MapLibrary.readWavesFromClasspath(key) ──▶ LevelWaves
        └─▶ GameController 按当前波取 groups → 出怪队列 → WaveManager 按时间轴出怪
```

- 一个关卡"有多少波" = 该关卡 `waves.json` 中 `waves` 数组的元素个数；
- 关卡目录缺 `waves.json` → **回退现有 `GameConfig` 全局行为**（保持可玩，见 §3.5）。

## 三、JSON 契约

### 3.1 文件位置

每张地图一份：`src/main/resources/maps/<key>/waves.json`（与 `path.json`、`spots.json` 并列，同受 `util.map.MapLibrary` 管理）。

### 3.2 顶层结构与字段

```json
{
  "name": "default_waves",
  "waves": [
    {
      "id": 1,
      "maxPrepMs": 5000,
      "groups": [
        { "type": "normal_enemy", "count": 3, "intervalMs": 1000 },
        { "type": "tank_enemy",   "count": 1, "intervalMs": 2500 }
      ]
    },
    {
      "id": 2,
      "maxPrepMs": 8000,
      "groups": [
        { "type": "normal_enemy", "count": 2, "intervalMs": 1200 },
        { "type": "boss_enemy",   "count": 1, "intervalMs": 1500 }
      ]
    }
  ]
}
```

| 路径 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 否（缺省 `"<key>_waves"`） | 关卡名，仅标识用 |
| `waves` | array | 是 | 波次列表，**数组顺序即游戏内波次顺序**；空数组=本关无波（不合法，见 §3.4） |
| `waves[].id` | int | 否 | 仅阅读用；**事实来源是数组下标**（第 k 项即第 k 波，id 应为 k），读取时不一致仅告警 |
| `waves[].maxPrepMs` | int | 否 | 该波开始前的准备倒计时上限（毫秒，≥0）。省略 → 取 `GameConfig.waveIntermissionMs` 全局默认。**第 1 波忽略本字段**（开局直接可手动开始） |
| `waves[].groups` | array | 是 | 有序出怪组，≥1 组 |
| `groups[].type` | string | 是 | 敌人 id，词汇表见 §4；未知 id 处理见 §3.5 |
| `groups[].count` | int | 是 | 本组连续出生的敌人数（≥1） |
| `groups[].intervalMs` | int | 是 | 本组内相邻两只的出生间隔（毫秒，>0）；count=1 时也须为正（作为"接下一组的节奏"，见 §3.3） |

### 3.3 出怪时间轴语义（组间"后组节奏接力"）

以 `T = 本波开始出怪时刻`（= 上一波清场 + 准备倒计时结束 / 玩家提前开波的瞬间）为起点：

- **第 1 只**敌人于 `T` 出生；
- 此后**每一只**的出生时刻 = 上一只出生时刻 +「负责生成这一只的组的 `intervalMs`」；
- 组内按 `count` 只连续出完，随后自动进入**下一组**——跨组的空隙同样 = 后一组自身的 `intervalMs`，因此整波是一条**无缝、节奏为"当前组间隔"**的时间轴，不会因切组产生爆发点或停顿空档；
- 组序 = `groups` 数组顺序；最后一组出完 = 该波出怪完毕（`isSpawning` 结束）。

示例时间轴（第 1 波 `normal×3@1000` → `tank×1@2500` → `boss×1@1500`）：

| 时刻（相对 T） | 出怪 |
|---|---|
| +0 ms | normal #1 |
| +1000 ms | normal #2 |
| +2000 ms | normal #3 |
| +4500 ms（2000+2500） | tank #1 |
| +6000 ms（4500+1500） | boss #1 |

> 结论：**任何"某只敌人"出生前，上一只与它之间必然隔着 = 将要出生这只所在组的 intervalMs**。该规则同时定义组内与组间，运行时/测试可用同一条公式校验。

### 3.4 校验规则（工具保存前拦截；加载时宽松）

| 规则 | 说明 |
|---|---|
| `waves` 非空 | 每关至少 1 波 |
| `groups` 非空 | 每波至少 1 组 |
| `count` ≥ 1 | 整数 |
| `intervalMs` > 0 | 整数，毫秒 |
| `maxPrepMs` ≥ 0 | 缺省回退规则见 3.2 |
| `type` ∈ 词汇表 | 未知 id 由工具标红禁止保存（见 §3.5 的运行期策略） |

### 3.5 容错与回退（运行期，不崩）

1. `maps/<key>/waves.json` 缺失/整体解析失败 → 回退现有 `GameConfig` 行为（`totalWaves`/`waveEnemyCount`/`waveSpawnIntervalMs` 等），并打警告；
2. 某条 wave 结构非法（缺 groups、count<1、intervalMs≤0）→ **跳过该波**并告警；
3. 某组 `type` 不在词汇表 → **跳过该组**并告警（不阻塞其他组出怪）；
4. 波数由此文件唯一决定；加载成功后运行时不再读 `GameConfig` 的波次全局值（A 集成时替换）。

## 四、敌人 id 词汇表与数值归属

waves.json 里**只写敌人 id**，不写任何数值。

| id（type） | 对应具体类 | AssetKey | 工具显示名 | 出怪接线状态 |
|---|---|---|---|---|
| `normal_enemy` | `model.enemy.NormalEnemy` | `NORMAL_ENEMY` | 普通敌人 | 已接入（现 spawnEnemy） |
| `fast_enemy` | `model.enemy.FastEnemy` | `FAST_ENEMY` | 快速敌人 | 待 A 接线 |
| `tank_enemy` | `model.enemy.TankEnemy` | `TANK_ENEMY` | 重甲敌人 | 待 A 接线 |
| `boss_enemy` | `model.enemy.BossEnemy` | `BOSS_ENEMY` | 首领敌人 | 待 A 接线 |

- **数值（HP/速度/近战攻击/冷却/赏金等）归属**：由 A 在 `GameConfig` 侧按 id 补齐每类敌人的构造参数（对齐《接口契约》"数值集中、实体类内不写死"）；**D 的工具与数据模型不感知数值**，只维护上方词汇表（id + 显示名，供下拉/校验）。
- 词汇表与代码类/AssetKey 同源命名（camel→snake），未来新增敌人 = 三处同步：类 + AssetKey + 词汇表（工具由此自动出现新选项）。

## 五、写入侧：数据模型与编辑工具（D 交付）

### 5.1 数据模型与仓库（放 `util.map`，运行期与工具共用）

- **`util.map.LevelWaves`**（数据类，仿 `MapRoute/TowerSpots` 模式）：
  - 结构：`name` + `List<Wave> waves`；`Wave { int id; long maxPrepMs; List<SpawnGroup> groups; }`；`SpawnGroup { String type; int count; long intervalMs; }`（附 getter/setter）；
  - JSON：`toJson()` / `fromJson(String)`（复用 `util.json.MiniJson`），输出顺序稳定、便于 diff；另提供 `loadFromClasspath(String)`（带缓存，同现有数据类）。
- **`util.map.MapLibrary` 扩展**（沿用现有 maps 分包仓库）：
  - 常量：`WAVES_FILE = "waves.json"`；
  - 方法：`wavesFile(key)`、`readWaves(key)`（repo 优先、退回 classpath）、`writeWaves(key, LevelWaves)`、`readWavesFromClasspath(key)`、以及供"该关是否有波次表"判断的 `exists` 复用。

### 5.2 编辑工具（放 `util.editor`，仿 AnimEditorTool 工程结构）

- 类：`util.editor.WaveEditorTool`（`main()` 转发嵌套 `WaveEditorApp extends Application`）+ 可选 `util.editor.WaveEditorLauncher`；
- 启动：改 `pom.xml` javafx 插件 `mainClass` 为 `com.kingdom.game.util.editor.WaveEditorTool` → `mvn javafx:run`（IDE 直跑不支持，同现有工具）。

**功能清单**：

| # | 功能 | 要求 |
|---|---|---|
| 1 | 关卡（地图）选择 | 读 `maps/index.json`（`MapLibrary.listMaps`）下拉选择/新建（复用 `MapLibrary.createMap` 流程） |
| 2 | 载入/新建 | 选中即载入该关 `waves.json`（`readWaves`）；无则新建空表模板（默认 1 波、`maxPrepMs` 取全局默认、1 组 normal×1@1000） |
| 3 | 波次列表 | ListView 展示 `第 k 波（id）`，支持：新增波（插到末尾）/删除/整波复制/上移/下移 |
| 4 | 单波字段 | `maxPrepMs` 输入（可留空=跟随全局默认），预览第 1 波提示"开局直接开始，本字段无效" |
| 5 | 出怪组表格 | 每波一张组表：列 = 敌人类型(下拉，词汇表含显示名)/数量/intervalMs；组行可增/删/上移/下移；行间即时提示该组预计耗时 count×intervalMs 与累计出怪数 |
| 6 | 时间轴预览 | 只读文本/列表：按 §3.3 公式生成 `时刻→敌人` 序列（便于设计者核对密度与 Boss 位置） |
| 7 | 校验 | 保存前按 §3.4 校验；错误弹窗/行标红，禁止写出 |
| 8 | 保存 | 经 `MapLibrary.writeWaves(key, waves)` 写回 `maps/<key>/waves.json`；另提供「另存为 JSON」 |
| 9 | 状态栏 | 当前文件路径 + 校验摘要 + "重启游戏生效"提示 |

## 六、读取侧：运行时契约（loader 归 D，接线归 A）

### 6.1 loader（D 交付，§5.1 已含）

`GameConfig` 构造时经 `MapLibrary.readWavesFromClasspath(key)` 得到 `LevelWaves`；缺失按 §3.5 回退。数据类与仓库本身即"读取规范"的实现，运行期**只读、带缓存、不抛异常**。

### 6.2 A 集成清单（D 交付后由 A 完成，不在本委托实现范围内）

1. `GameState.totalWaves` 改由关卡波数（`LevelWaves.waves.size()`）提供（胜利判定随之变化）；
2. `GameController.spawnEnemy` 由"固定 NormalEnemy"改为按 `SpawnGroup.type` 查词汇表建对应敌人（数值取自 GameConfig 按 id 补齐的槽位）；
3. `WaveManager.beginWave` 升级：由"数量+统一间隔"改为消费**出怪队列**（该波 groups 按 §3.3 展开的时间轴），或新增 `beginWave(Wave wave)` 逐组推进；
4. 波间准备：下一波 `maxPrepMs` 接入现有 `getNextWaveCountdownMs/getEarlyStartBonus` 波间倒计时机制（第 1 波仍可直接开始；提前开波奖励上限沿用 `GameConfig.earlyStartRewardCap`，整局一个值，不做每波）；
5. `resetGame`/波次推进边界（第 N 波出怪完毕且清场 → 胜利）复用现逻辑，仅数据源替换。
