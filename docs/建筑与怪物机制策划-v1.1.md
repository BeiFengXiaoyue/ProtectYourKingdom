## 2. 建筑机制策划

### 2.1 三类塔定位与克制关系

| 塔 | 核心定位 | 克制 | 弱势 |
| -- | ---- | ---- | ---- |
| 箭塔 | 单体高速物理，DPS 稳定，造价低 | 快速敌人、低血单位 | 重甲（吃物理减伤） |
| 炮塔 | 范围溅射，慢攻速高爆发 | 重甲、密集群体 | 快速（溅射难命中、攻速慢） |
| 兵营 | 生成士兵阻挡路径，拖延时间 | Boss、单体高威胁 | 范围伤害敌人、士兵被清场 |

**核心克制规则：**

- 重甲敌人拥有**物理减伤**（比例键 `balance.json` → `tankPhysicalReduction`）→ 箭塔伤害被打折，实现见 `LivingEntity.damageTakenMultiplier` + `TankEnemy` 构造期取值；
- 炮塔拥有**破甲 = 无视物理减伤**（`Bomb.onHit` 走 `takeDamage(dmg, true)`，打满面板值）。
  > 📌 **口径以「无视减伤」为准**：曾议的「对重甲额外 +30% 伤害」**未采用**——当前是「打满面板值」，不是「面板值 × 增益」。
  > 若后续要加这笔加成，改动很小（命中重甲时伤害乘一个可入 JSON 的比例），需单独拍板。
- 快速敌人速度快，考验塔的攻击间隔（DPS 而非单发伤害）。

### 2.2 箭塔升级路线

| 等级 | 数值键 | 特殊能力 |
| ---- | ---- | ---- |
| 1 级（初始） | `arrowL1` | 单体追踪箭 |
| 2 级 | `arrowL2` | — |
| 3 级 | `arrowL3` | 连锁箭（主目标命中后溅射附近目标，目标数与伤害比例可配） |

> 设计逻辑：箭塔 3 级前是纯单体 DPS，3 级给连锁能力弥补后期群体乏力，但不替代炮塔的范围伤害定位。

### 2.3 炮塔升级路线

| 等级 | 数值键 | 溅射半径键（`balance.json`） | 特殊能力 |
| ---- | ---- | ---- | ---- |
| 1 级 | `cannonL1` | `cannonSplashRadius` | 范围爆炸 |
| 2 级 | `cannonL2` | `eliteCannonSplashRadius` | — |
| 3 级 | `cannonL3` | `masterCannonSplashRadius` | 燃烧 DoT（每秒伤害与持续时长可配） |

- 设计意图：单发高爆发、攻速慢；对密集群体收益显著，对快速目标效率低。
- 溅射半径由 `balance.json` 驱动（`Bomb` 内**无**硬编码半径）。

### 2.4 兵营升级路线

| 等级 | 数值键 | 士兵数 | 特殊能力 |
| ---- | ---- | ---- | ---- |
| 1 级 | `barrackL1` | `maxSoldiers` | 基础阻挡 |
| 2 级 | `barrackL2` | `maxSoldiers` | — |
| 3 级 | `barrackL3` | `maxSoldiers` | 治疗光环（每秒回血与半径可配） |

- 士兵的 HP / 速度 / 攻击 / 冷却取本兵营等级字段（`soldierHp` / `soldierSpeed` / `soldierAttack` / `soldierCooldown`）；
- 出场与重生间隔取 `spawnIntervalMs`（当前口径 5s）；
- **核心机制**：士兵碰到敌人时敌人进入「拦截」状态（`Enemy` 的 `isEngaged` 逻辑），**完全停止前进**并与士兵近战。
  兵营的核心价值是**拖延敌人走完全程的时间，为其他塔争取输出窗口**。

### 2.5 经济平衡

| 项 | 数值键 | 设计逻辑 |
| ---- | ---- | ---- |
| 初始金币 | `balance.json` → `initialGold` | 按各级造价，开局可选择「多座 1 级塔」或「少数高级塔」 |
| 各敌人赏金 | `balance.json` → `{normal,fast,tank,boss}GoldReward` | 越难杀 / 威胁越大，赏金越高 |
| 出售返还 | — | 固定为 `totalCost / 2`（代码实现） |

> 设计目标：整局收益支持「建 3~4 座塔 + 若干次升级」，经济紧张但不卡死。具体数值随 JSON 调整，本文档不再给估算。

## 3. 怪物机制策划

### 3.1 四类敌人的设计定位

| 敌人 | 数值键前缀（`balance.json`） | 体型 | 特殊机制 |
| ---- | ---- | ---- | ---- |
| 普通 | `normal*` | 中 | 无 |
| 快速 | `fast*` | 小 | 速度约为普通 2 倍，考验塔攻速 |
| 重甲 | `tank*` | 大 | **物理减伤**（`tankPhysicalReduction`）；炮塔无视减伤 |
| Boss | `boss*` | 最大 | 半血狂暴（速度倍率 + 攻击间隔削减）+ 震地（周期眩晕全塔）；召唤**不做** |

> **攻击力 / 攻击冷却**由 `balance.json` 的 8 个 `{type}AttackDamage` / `{type}AttackCooldownMs` 键决定，实体类内**已无写死值**；改值编辑 JSON 后重启生效。

### 3.2 Boss 技能设计

| 技能 | 触发条件 | 效果 | 实现状态 |
| ---- | ---- | ---- | ---- |
| 狂暴 | HP ≤ 阈值（类常量 `ENRAGE_HP_RATIO`） | 速度 ×`ENRAGE_SPEED_MULTIPLIER`；攻击冷却按 `balance.json` → `bossEnrageAttackCooldownCut` 削减 | ✅ 已实现（阈值与倍率仍为类常量，未配置化） |
| 震地 | 狂暴后每隔 `balance.json` → `bossStompIntervalMs` | 全屏红闪 + 震动，**眩晕所有塔**（时长见 `GameController.BOSS_STOMP_STUN_MS`） | ✅ 已实现（`BossEnemy.consumeStompRequest()` → `GameController.settleBossStompRequests()` → `tower.stun(...)`；狂暴当刻先震一次） |
| 召唤 | — | 在出生点生成普通敌人 | ⏸ **已裁定不做**（决议结果，非缺口） |

> 设计逻辑：Boss 本身 HP 高走得慢，玩家有充足时间输出；半血后狂暴 + 震地制造压力窗口。

### 3.3 难度曲线设计意图

难度**只通过出怪种类、数量与出场间隔**体现——敌人属性（HP / 速度 / 赏金）为固定值，**不随波次递增**（已决定不做递增）。

曲线拐点的设计意图（**不绑定具体波号**，实际波次由各关 `waves.json` 决定）：

| 拐点 | 设计意图 |
| ---- | ---- |
| 首次出现快速敌人 | 玩家需要第二座塔或更高攻速 |
| 首次出现重甲 | 箭塔效率骤降，逼玩家建炮塔或集火 |
| 重甲潮 | 纯箭塔阵容几乎必漏，强制炮塔 |
| Boss 战 | 需兵营拖延走位 + 炮塔爆发 + 箭塔清场，单一塔型无法通关 |

> ℹ️ **波次不写死**：某关有几波、每波出什么，**唯一来源是该关 `maps/<key>/waves.json`**（见《关卡波次配置规范》）。
> 当前 `maps/default/waves.json` 是联调用的**测试数据**，不是最终关卡设计。

## 4. 平衡验证方法

数值改动后按下述方法自验（本文档不给具体计算结果，避免与 JSON 脱节）：

1. **走完全程时间** = 路径总长度 ÷ 敌人速度。路径长度由该关 `path.json` 的拐点连线累计得出（各关不同）。
2. **单塔击杀时间** = 敌人有效 HP ÷ 该塔对该敌人的有效 DPS：
   - 有效 HP 需考虑物理减伤（箭矢打折、炮塔破甲）；
   - 有效 DPS = 伤害 ÷ 冷却 × 命中率（溅射对单体只用单发伤害）。
3. 比较「击杀时间」与「走完全程时间」，判断该配比是**轻松 / 紧张 / 必漏**；再检查经济是否支撑对应数量与等级的塔。
4. 关注结论（与具体数值无关的定性结论）：
   - 单座箭塔能处理普通与快速，但面对重甲效率骤降；
   - 炮塔对重甲的有效输出显著高于箭塔，体现克制；
   - Boss 战必须多类型塔配合，单一塔型无法通关。
