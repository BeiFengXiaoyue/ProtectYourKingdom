# 实体视觉尺寸配置规范（素材方 E 交付）

> 归属：素材与音效（E）｜读写通道归集成（A）
> 适用版本：dev
> 任务性质：把**实体视觉大小（宽/高）从代码写死改为 JSON 配置**。
> **状态：已实现**——`util/asset/SizeTable` + `assets/sizes.json`，运行期按类名查表并回退 `default`。
> **数值口径**：各类现行尺寸一律以 `src/main/resources/assets/sizes.json` 为准，本文档不抄写具体数字。

---

## 一、背景与问题

实体的渲染尺寸、碰撞半径、头顶血条宽度全部以 `GameObject.width / height` 为准，而这两个值原先被**代码写死**在两处：

| 写死位置 | 原状 | 后果 |
|---|---|---|
| `GameObject(x, y)` 构造器 | 无条件落到默认宽高 | 没显式设尺寸的类永远是默认大小 |
| 各子类构造器内的 `setWidth/setHeight` | 分散在 Soldier / FastEnemy / TankEnemy / BossEnemy / Arrow / Bomb | 各实体大小关系埋在实体类里，分散难维护 |

**影响**：素材方替换/调整美术后，想改「显示多大」必须改 Java、重新编译，违背「素材插入通道只放文件、不改逻辑」的既有分工；素材侧没有可操作的旋钮；新增实体类时大小容易被遗忘。

**根因**：渲染缩放（`GameObject.drawSprite`）、碰撞半径（`LivingEntity.getCollisionRadius()`）、血条宽度均取自 `width/height`，而该数据源被写死。

---

## 二、目标与总体方案

**一句话目标**：实体视觉大小由素材方维护的配置文件唯一决定，Java 代码不再写死任何实体尺寸。

```
assets/sizes.json（素材方维护，置于 resources）
        │  classpath 读取（懒加载 + 缓存）
        ▼
util.asset.SizeTable（缺失/解析失败一律回退默认，不抛异常）
        │  entryFor(实体运行时类) 以 getSimpleName() 命中
        ▼
GameObject(x, y) 构造期自动套用 width / height
```

**改造范围原则**：
- 代码不写死尺寸；子类里的 `setWidth/setHeight` 已全部删除；
- 此后素材方调尺寸 = 改 `assets/sizes.json`（推荐用 §七 工具可视化编辑），**不碰 Java**；
- 新增实体类 → 打开工具即自动出现在清单（反射枚举），保存后自动补出条目（默认跟随 `default`），无需手工维护清单。

## 三、尺寸配置 JSON 契约

### 3.1 文件与位置

- 唯一文件：`src/main/resources/assets/sizes.json`。
- 编辑器/开发期读写**仓库文件**；游戏运行期从 **classpath**（`/assets/sizes.json`）读同一份。

### 3.2 顶层结构与字段

```json
{
  "default": { "width": 20, "height": 20 },
  "entities": {
    "NormalEnemy": { "width": 20, "height": 20 },
    "Soldier":     { "width": 18, "height": 18 },
    "Bomb":        { "width": 14, "height": 14 }
  }
}
```

> ⚠️ 上面是**结构示意**（数字为首版交付前的旧值），**不是现行值**；现行值请看 `assets/sizes.json` 文件本身。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `default` | `{ "width": number, "height": number }` | 否 | 未单独配置的实体的兜底尺寸 |
| `entities` | `{ "类名": { "width": number, "height": number }, … }` | 否 | 逐类配置；键为 GameObject 具体类的类名 |
| `width` / `height` | number（条目内） | 是 | 画布像素，>0；允许小数 |

### 3.3 key 语义与枚举来源

- 键 = 该类继承链上**最末具体类**的 `getSimpleName()`（大小写敏感）。例：`NormalEnemy`、`EliteArrowTower`（精英塔与 1 级塔是独立类、可各设尺寸，即使共用同一贴图）。
- 「现有的所有从 GameObject 继承出来的具体类」来源 = **反射扫描 `com.kingdom.game.model`**（含 `enemy / ally / tower / projectile` 子包）的编译产物，过滤规则：`GameObject.class.isAssignableFrom(cls)` 且**非抽象类、非接口、非内部类**。
- 当前应枚举出 **18 个**具体类：
  - 敌人 4：`NormalEnemy` / `FastEnemy` / `TankEnemy` / `BossEnemy`
  - 友方 3：`Soldier` / `EliteSoldier` / `RoyalSoldier`
  - 塔 9：`ArrowTower` / `CannonTower` / `Barrack` + 各自 `Elite*` / `Master*`
  - 投射物 2：`Arrow` / `Bomb`

  后续新增实体类自动出现在清单中，**不要求手工维护**。

### 3.4 回退规则（严格顺序）

1. `entities[类名]` 存在且宽高合法 → 使用该项；
2. 否则使用顶层 `default`；
3. `default` 缺失或非法 → 使用内置兜底（默认宽高）；
4. 条目内 `width/height` 任一缺失、非正数或解析失败 → 视同「该项未配置」，走上一级回退。

回退全程**不抛异常、不阻断游戏启动**；加载失败仅打印警告（参考 `util/asset/Assets` 的容错风格）。

### 3.5 数值语义（务必理解）

- 实体以 `(x, y)` 为**中心**，把贴图缩放到 `width × height` 绘制（`GameObject.drawSprite`）；无贴图时色块回退画的是同一个矩形；
- **碰撞半径** `= max(width, height) / 2`（`LivingEntity.getCollisionRadius`）——改尺寸会同步影响敌人拦截/近战手感；
- **头顶血条**宽度与绘制位置随 `width` 变化。
- **生效时机**：实体**构造期**读取一次并固化到实例 `width/height`；修改 JSON 后**重启游戏生效**，运行中不逐帧查表。

> 结论：把一个单位改大，不止「画得大」，也会更难被越过。尺寸数值应与玩法负责人核对后再提交，避免单纯追求美术效果破坏数值手感。

## 四、现状与缺口

- 现行尺寸表见 `src/main/resources/assets/sizes.json`（18 条 + `default`），三族 9 个塔、三档士兵均已逐条登记，**L3 大师塔不再回退 `default`**。
- 若某类未登记，会在实体构造期回退 `default` 并在画面/碰撞上体现为默认大小——属**预期容错**，不是崩溃。
- `towers/arrow_tower.json` 等动画表与尺寸无关（尺寸只管宽高，不管帧图）。

## 五、运行期行为契约（代码改造清单）

| # | 文件 | 改动要求 | 状态 |
|---|---|---|---|
| 1 | `util/asset/SizeTable.java` | 尺寸表仓库，API 见 §六；**无 JavaFX 依赖**，懒加载静态单例 | ✅ |
| 2 | `model/GameObject.java` | `GameObject(x, y)` 改为字段直赋 + `SizeTable.entryFor(getClass())` 套用 `width/height`；四参构造 `GameObject(x, y, w, h)` **保留** | ✅ |
| 3–8 | `Soldier` / `FastEnemy` / `TankEnemy` / `BossEnemy` / `Arrow` / `Bomb` | 删除各自的 `setWidth/setHeight` 写死值，注释注明「尺寸见 `assets/sizes.json`」 | ✅ |
| 9 | `view/Main.java` | 启动时调用一次 `SizeTable.getInstance().preload()`（与 `Assets.preload()` 并列）；缺文件仅警告、不阻断 | ✅ |
| 10 | `util/editor/SizeEditorTool.java` | 可视化尺寸设计工具，需求见 §七 | ✅ |

- JSON 解析**复用 `util/json/MiniJson`**，不引入第三方 JSON 库；
- 本任务只管**宽/高**；实体 HP / 速度 / 造价等数值归 `config/balance.json` 与 `config/tower.json`（见《数值配置 JSON 化规范》），一律不动。
- `GameObject` 等公共抽象类改动需集成负责人过手。

## 六、`SizeTable` API

| API | 面向 | 说明 |
|---|---|---|
| `void preload()` | 运行期 | 触发一次加载并缓存；缺文件打印警告 |
| `Entry entryFor(Class<? extends GameObject> cls)` | 运行期 | 按 `getSimpleName()` 命中条目；未命中返回 `default`（内置兜底时仍返回非 null） |
| `Entry`（内部类） | — | `className / width / height` + getter |
| `SizeTable read()` | 编辑器 | 优先读仓库文件 `src/main/resources/assets/sizes.json`，否则退回 classpath，否则返回「仅 default」的空表（不抛异常） |
| `boolean saveToRepo()` | 编辑器 | 从当前工作目录向上找 `src/main/resources`（同 `AnimLibrary.findRepoResourcesDir()` 规则），`mkdirs` + 覆盖写回；失败返回 false |
| 条目增删改查（`get/put/remove/classNameList`） | 编辑器 | 供工具读写内存表；保存时**保留文件里已有但本次未枚举到的条目**，同 key 覆盖 |

运行时查找与编辑器读表共用同一种回退语义。

## 七、尺寸设计工具：`util.editor.SizeEditorTool`

工程结构仿 `util.editor.AnimEditorTool`（`main()` 转发嵌套 `Application`，规避 JavaFX 模块检查）。

| # | 功能 | 要求 |
|---|---|---|
| 1 | 自动枚举类 | 反射扫描 `com.kingdom.game.model/**` 的 `.class`，过滤出 GameObject 具体子类（非抽象、非接口、跳过 `$` 内部类） |
| 2 | 分组展示 | 按子包归组：`enemy`→敌人、`ally`→友方、`tower`→防御塔、`projectile`→投射物；行内显示「类名 + 当前配置值（或 `跟随 default`）」 |
| 3 | 编辑尺寸 | 选中类 → 宽/高输入框（允许小数，留空 = 回退 default），改动即时更新左侧行内显示 |
| 4 | 贴图预览 | 以当前 W×H 预览该类贴图：类名 camel→snake 后拼 `assets/<蛇形类名>.png`（如 `EliteArrowTower → elite_arrow_tower.png`）；缺图给提示不阻塞 |
| 5 | 按原图尺寸 | 一键读取该贴图实际像素并填入宽/高 |
| 6 | 保存 | 合并写回 `src/main/resources/assets/sizes.json`（保留未知条目、同 key 覆盖），提示「重启游戏生效」；提供「另存为…」导出 |
| 7 | 状态/错误 | 底部状态栏 + 必要错误弹窗 |

**启动方式**：把 `pom.xml` 的 javafx 插件 `mainClass` 改为 `com.kingdom.game.util.editor.SizeEditorTool` 后执行 `mvn javafx:run`；用完改回 `com.kingdom.game.view.Main`。

## 八、验收标准

1. 编译通过，无新增编译警告；
2. 删除/缺失 `assets/sizes.json` → 全部实体回退默认，**不抛异常、能正常进游戏**；
3. 改 JSON 中某类宽高 → 重启 → 该类新建实体按新尺寸渲染，血条宽度与碰撞半径随之变化；
4. JSON 中删除某类条目 → 该类回退 `default`；
5. `SizeEditorTool` 清单与 model 下 18 个具体子类一致；临时新增一个实体子类（不碰工具代码）重新枚举即可出现；
6. 工具内改尺寸并保存 → 文件格式与 §3.2 一致，重启后表现与编辑值一致；
7. 代码里**搜索不到**残留的写死尺寸（内置兜底仅允许存在于 `SizeTable` 与 JSON `default`）。

---

## 九、范围红线（不做清单）

- 不改 `config/balance.json` / `config/tower.json` 中的任何数值，不改 `maps/` 地图配置；
- 不实现/改动渲染叠层动画（见《单位行为动画-渲染层设计》），本轮与动画无关；
- 不改实体战斗数值、索敌/移动/攻击逻辑、碰撞反应规则（仅「宽高数据源变化导致半径变化」属本任务预期）；
- **禁止新增第二套并行尺寸通道**——不得在别处再写死尺寸，或出现第二份大小配置；
- 公共抽象类改动需集成负责人过手。
