# 实体视觉尺寸配置规范（素材方 E 交付）

> 提出：集成/架构（A）｜执行：素材与音效（E）｜日期：2026-09-09
> 适用版本：dev
> 任务性质：把**实体视觉大小（宽/高）从代码写死改为 JSON 配置**的规范与交付说明。本文档即派工单，素材方按 §三~§七 契约实施，按 §八 验收。

---

## 一、背景与问题

实体的渲染尺寸、碰撞半径、头顶血条宽度全部以 `GameObject.width / height` 为准，但目前这两个值被**代码写死**在两处：

| 写死位置 | 现状 | 后果 |
|---|---|---|
| `GameObject(x, y)` 构造器（`GameObject.java:34-36`） | 无条件落到 `this(x, y, 20, 20)` | 塔、普通敌人等一切“没显式设尺寸”的类永远 20×20 |
| 各子类构造器内的 `setWidth/setHeight` | Soldier 18、FastEnemy 16、TankEnemy 30、BossEnemy 46、Arrow 8、Bomb 14 | 各实体大小关系埋在实体类里，分散难维护 |

**影响**：
1. 素材方替换/调整美术后，想改“显示多大”必须改 Java、重新编译，违背“素材插入通道只放文件、不改逻辑”的既有分工（见 `docs/接口契约与抽象类说明.md` §1）；
2. 素材插入通道（`AssetKey` + `Assets`）只决定“有没有图”，不决定“画多大”，素材侧没有可操作的旋钮；
3. 新增实体类时大小很容易被遗忘或各写各的。

**根因**：渲染缩放（`GameObject.drawSprite`）、碰撞半径（`LivingEntity.getCollisionRadius() = max(w,h)/2`）、血条宽度均取自 `width/height`，而该数据源被写死。

---

## 二、目标与总体方案

**一句话目标**：实体视觉大小由素材方维护的配置文件唯一决定，Java 代码不再写死任何实体尺寸。

**数据流**：

```
assets/sizes.json（素材方维护，置于 resources）
        │  classpath 读取（懒加载 + 缓存）
        ▼
util.asset.SizeTable（缺失/解析失败一律回退默认，不抛异常）
        │  entryFor(实体运行时类).getSimpleName() 命中
        ▼
GameObject(x, y) 构造期自动套用 width / height
```

**改造范围原则**：
- 代码不写死尺寸；删除子类里所有 `setWidth/setHeight`；
- 首版 JSON 数值 = 当前代码行为（§四种子表），交付后**视觉与碰撞表现完全不变**；
- 此后素材方调尺寸 = 改 `assets/sizes.json`（推荐用 §七 工具可视化编辑），**不碰 Java**；
- 新增实体类 → 打开工具即自动出现在清单（反射枚举），保存后自动补出条目（默认跟随 `default`），无需手工维护清单。

## 三、尺寸配置 JSON 契约

### 3.1 文件与位置

- 唯一文件：`src/main/resources/assets/sizes.json`。
- 编辑器/开发期读写**仓库文件**；游戏运行期从 **classpath**（`/assets/sizes.json`）读同一份（Maven 自动把 `src/main/resources` 打进 classpath）。

### 3.2 顶层结构与字段

```json
{
  "default": { "width": 20, "height": 20 },
  "entities": {
    "NormalEnemy": { "width": 20, "height": 20 },
    "Soldier":     { "width": 18, "height": 18 },
    "Bomb":        { "width": 14, "height": 14 }
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `default` | `{ "width": number, "height": number }` | 否（缺省按 20×20） | 未单独配置的实体的兜底尺寸 |
| `entities` | `{ "类名": { "width": number, "height": number }, … }` | 否 | 逐类配置；键为 GameObject 具体类的类名 |
| `width` / `height` | number | 条目内必填 | 画布像素，>0；允许小数 |

### 3.3 key 语义与枚举来源

- 键 = 该类继承链上**最末具体类**的 `getSimpleName()`（大小写敏感）。例：`NormalEnemy`、`EliteArrowTower`（精英塔与 1 级塔是独立类、可各设尺寸，即使共用同一贴图）。
- “现有的所有从 GameObject 继承出来的具体类”来源 = **反射扫描 `com.kingdom.game.model`**（含 `enemy / ally / tower / projectile` 子包）的编译产物，过滤规则：`GameObject.class.isAssignableFrom(cls)` 且**非抽象类、非接口、非内部类**。
- 当前应枚举出 **13 个**具体类（清单见 §四）；后续新增实体类自动出现在清单中，**不要求手工维护**。

### 3.4 回退规则（严格顺序）

1. `entities[类名]` 存在且宽高合法 → 使用该项；
2. 否则使用顶层 `default`；
3. `default` 缺失或非法 → 使用内置兜底 **20×20**；
4. 条目内 `width/height` 任一缺失、非正数或解析失败 → 视同“该项未配置”，走上一级回退。

回退全程**不抛异常、不阻断游戏启动**；加载失败仅打印警告（参考 `util/asset/Assets` 的容错风格）。

### 3.5 数值语义（务必理解）

- 实体以 `(x, y)` 为**中心**，把贴图缩放到 `width × height` 绘制（`GameObject.drawSprite`）；无贴图时色块回退画的是同一个矩形；
- **碰撞半径** `= max(width, height) / 2`（`LivingEntity.getCollisionRadius`）——改尺寸会同步影响敌人拦截/近战手感；
- **头顶血条**宽度与绘制位置随 `width` 变化。

> 结论：把一个单位改大，不止“画得大”，也会更难被越过。尺寸数值表应与玩法组（A）核对后再提交，避免单纯追求美术效果破坏数值手感。

- **生效时机**：实体**构造期**读取一次并固化到实例 `width/height`；修改 JSON 后**重启游戏生效**，运行中不逐帧查表。

## 四、当前种子数值表（首版 JSON 必须按此导出）

首版 `assets/sizes.json` 的 `entities` 含全部 13 类，每类数值 = 现在代码写死的值，保证改造后视觉与碰撞**与交付前完全一致**。

| 分组 | 具体类 | 现代码尺寸（宽×高） | 种子 JSON 值 |
|---|---|---|---|
| 敌人 `enemy` | `NormalEnemy` | 默认 20×20 | 20×20 |
| 敌人 | `FastEnemy` | 16×16 | 16×16 |
| 敌人 | `TankEnemy` | 30×30 | 30×30 |
| 敌人 | `BossEnemy` | 46×46 | 46×46 |
| 友方 `ally` | `Soldier` | 18×18 | 18×18 |
| 防御塔 `tower` | `ArrowTower` | 默认 20×20 | 20×20 |
| 防御塔 | `CannonTower` | 默认 20×20 | 20×20 |
| 防御塔 | `Barrack` | 默认 20×20 | 20×20 |
| 防御塔 | `EliteArrowTower` | 默认 20×20 | 20×20 |
| 防御塔 | `EliteCannonTower` | 默认 20×20 | 20×20 |

| 投射物 `projectile` | `Arrow` | 8×8 | 8×8 |

## 五、运行期行为契约（代码改造清单）

| # | 文件 | 改动要求 |
|---|---|---|
| 1 | `util/asset/SizeTable.java` **（新增）** | 尺寸表仓库，API 见 §六；**无 JavaFX 依赖**，懒加载静态单例 |
| 2 | `model/GameObject.java` | `GameObject(x, y)` 改为字段直赋 + `SizeTable.entryFor(getClass())` 套用 `width/height`；四参构造 `GameObject(x, y, w, h)` **保留**（供未来代码显式指定；当前无任何子类使用，不必为其设计默认值） |
| 3 | `model/ally/Soldier.java` | 删除 `setWidth(18); setHeight(18);`，注释注明“尺寸见 assets/sizes.json” |
| 4 | `model/enemy/FastEnemy.java` | 删除 `16×16` 的 `setWidth/setHeight` |
| 5 | `model/enemy/TankEnemy.java` | 删除 `30×30` 的 `setWidth/setHeight` |
| 6 | `model/enemy/BossEnemy.java` | 删除 `46×46` 的 `setWidth/setHeight` |
| 7 | `model/projectile/Arrow.java` | 删除 `8×8` 的 `setWidth/setHeight` |
| 8 | `model/projectile/Bomb.java` | 删除 `14×14` 的 `setWidth/setHeight` |
| 9 | `view/Main.java` | 启动时调用一次 `SizeTable.preload()`（可与 `Assets.preload()` 并列）；缺文件仅警告、不阻断 |
| 10 | `util/editor/SizeEditorTool.java` **（新增）** | 可视化尺寸设计工具，需求见 §七 |

**实现要求**：
- JSON 解析**复用 `util/json/MiniJson`**（与 `AnimTable`/`MapLibrary` 一致），不引入第三方 JSON 库；
- 删除子类 `setWidth/setHeight` 后，若 JSON 缺失对应条目，该类会回退到 `default`/20——这是**预期**容错行为，不是 bug；
- 本任务只管**宽/高**。实体 HP/速度/造价等数值仍归 `GameConfig` 与实体构造器，一律不动。

> 红线提醒：`GameObject` 等公共抽象类**仅 A 可改**。E 完成实现后提交 diff，由 A review 后合入（见 §九）。

## 六、`SizeTable` 建议 API（供 E 实现参考）

| API | 面向 | 说明 |
|---|---|---|
| `void preload()` | 运行期 | 触发一次加载并缓存；缺文件打印警告 |
| `Entry entryFor(Class<? extends GameObject> cls)` | 运行期 | 按 `getSimpleName()` 命中条目；未命中返回 default（内置兜底 20×20 时仍返回非 null） |
| `Entry`（内部类） | — | `String className / double width / double height` + getter |
| `SizeTable read()` | 编辑器 | 优先读仓库文件 `src/main/resources/assets/sizes.json`，否则退回 classpath，否则返回“仅 default”的空表（不抛异常） |
| `boolean saveToRepo()` | 编辑器 | 从当前工作目录向上找 `src/main/resources`（同 `AnimLibrary.findRepoResourcesDir()` 规则），`mkdirs` + 覆盖写回；失败返回 false |
| 条目增删改查（`get/put/remove/classNameList`） | 编辑器 | 供工具读写内存表；保存时**保留文件里已有但本次未枚举到的条目**，同 key 覆盖 |

运行时查找与编辑器读表共用同一种“default → 20×20”回退语义。

## 七、尺寸设计工具需求：`util.editor.SizeEditorTool`

工程结构仿 `util.editor.AnimEditorTool`（`public final` 工具类 + `main()` 转发 `Application.launch(SizeEditorApp.class)`，窗口本体为嵌套 `public static final SizeEditorApp extends Application`，规避 JavaFX 模块检查）。

**功能清单**：

| # | 功能 | 要求 |
|---|---|---|
| 1 | 自动枚举类 | 反射扫描 GameObject 代码源目录下 `com.kingdom.game.model/**` 的全部 `.class`，过滤出 GameObject 具体子类（非抽象、非接口、跳过 `$` 内部类） |
| 2 | 分组展示 | 按子包归组：`enemy`→敌人、`ally`→友方、`tower`→防御塔、`projectile`→投射物；行内显示“类名 + 当前配置值（或 `跟随 default`）” |
| 3 | 编辑尺寸 | 选中类 → 宽/高输入框（允许小数，留空=回退 default），改动即时更新左侧行内显示 |
| 4 | 贴图预览 | 以当前 W×H 预览该类贴图：类名 camel→snake 后拼 `assets/<蛇形类名>.png`（如 `EliteArrowTower → elite_arrow_tower.png`）；缺图给提示不阻塞 |
| 5 | 按原图尺寸 | 一键读取该贴图实际像素并填入宽/高（素材方常用入口） |
| 6 | 保存 | 合并写回 `src/main/resources/assets/sizes.json`（保留未知条目、同 key 覆盖），提示“重启游戏生效”；提供「另存为…」导出 |
| 7 | 状态/错误 | 底部状态栏 + 必要错误弹窗（对齐 AnimEditorTool 交互习惯） |

**启动方式**：把 `pom.xml` 的 javafx 插件 `mainClass` 改为 `com.kingdom.game.util.editor.SizeEditorTool` 后执行 `mvn javafx:run`；用完改回 `com.kingdom.game.view.Main`。IDE 直接运行不可用（JavaFX 模块检查），与现有工具一致。

## 八、验收标准（Definition of Done）

1. `mvn -q compile` 通过，无新增编译警告；
2. 首版 `assets/sizes.json` 与 §四种子表一致；删除 6 处 `setWidth/setHeight` 后启动游戏，**画面表现、血条、碰撞手感与改造前一致**；
3. 改 JSON 中某类宽高 → 重启 → 该类新建实体按新尺寸渲染，血条宽度与碰撞半径随之变化；
4. 删除整个 `assets/sizes.json`（模拟缺失）→ 全部实体回退默认，**不抛异常、能正常进游戏**；
5. JSON 中删除某类条目 → 该类回退 `default`；
6. `SizeEditorTool` 打开后清单与 model 下 13 个具体子类一致；临时新增一个实体子类（不碰工具代码）重新枚举即可出现；
7. 工具内改尺寸并保存 → 文件格式与 §3.2 一致，重启游戏后表现与编辑值一致；
8. 代码里**搜索不到**残留的写死尺寸（20×20 仅允许存在于 `SizeTable` 内置兜底与 JSON `default`）。

> README「运行工具」表的补充行与本文档回链，由提出方（A）在 E 合入后顺带维护，不阻塞本任务验收。

## 九、范围红线（不做清单）

- 不改动 `GameConfig` 及其中任何数值（画布/金币/生命/波次/敌人数值等），不改 `maps/` 地图配置；
- 不实现/改动渲染叠层动画（`docs/单位行为动画-渲染层设计.md` 中的 `UnitPoseResolver`/`UnitAnimator` 等），本轮与动画无关；
- 不改实体战斗数值、索敌/移动/攻击逻辑、碰撞反应规则（仅“宽高数据源变化导致半径变化”属于本任务预期）；
- **禁止新增第二套并行尺寸通道**——不得在别处再写死尺寸，或出现第二份大小配置；
- `GameObject` 等公共抽象类仅 A 可改：E 交付 diff，由 A review 合入。
