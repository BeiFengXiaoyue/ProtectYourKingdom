# 友方士兵子系统说明

> 归属：友方单位开发
> 版本：v1.0
> 覆盖：1 级 `Soldier` / 2 级 `EliteSoldier` / 3 级 `RoyalSoldier`
> 本文档说明**三档士兵的数值、契约与使用方式**，供架构师 A / 防御塔 C / UI D / 素材 E 对照。
> 与《防御塔子系统说明》互补：那篇讲塔与升级链，本篇讲塔里"产出的兵"。

---

## 1. 三档士兵一览

| 等级 | 类 | 默认 HP | 速度 px/s | 攻击 | 冷却 | 索敌视野 | 体型 | 显示名 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 级 | `Soldier` | 70（由兵营传入，类内不写死） | 60 | 10 | 800ms | 90 | 18×18 | 士兵 |
| 2 级 | `EliteSoldier` | 100 | 65 | 14 | 700ms | 120 | 20×20 | 精英士兵 |
| 3 级 | `RoyalSoldier` | 150 | 72 | 20 | 620ms | 150 | 22×22 | 皇家卫士 |

- 三档数值**依次提高**（HP 70 → 100 → 150，攻击 10 → 14 → 20，冷却 800 → 700 → 620ms，视野 90 → 120 → 150）。
- 1 级沿用现状：数值**由生产方注入**（`Barrack` 传 70/60/10/800，`EliteBarrack` 传 100/65/14/700），
  类内不写死；2/3 级额外提供**类内默认档案**（`DEFAULT_HP` 等 public 常量）作直接实例化时的兜底，
  同时保留全参构造供生产方注入——数值口径与 1 级一致。
- 2 级档案刻意与《防御塔子系统说明》§14 的 `EliteBarrack` 士兵参数（100/65/14/700）对齐，
  因此把 2 级兵营的产出换成本类**不改变战斗数值**。

## 2. 分级方式：三档并列，互不继承（重要）

三档士兵都是 `Ally` 的**直接子类**，彼此没有继承关系：

```
Ally（抽象：索敌策略 + 对敌碰撞反应）
├── Soldier        1 级
├── EliteSoldier   2 级   ← 不继承 Soldier
└── RoyalSoldier   3 级   ← 不继承 EliteSoldier
```

**为什么这么分**：每档的数值、视野、体型、渲染各自独立，改 2 级不会波及 1/3 级；
代价是索敌/追击/回防三段逻辑**每档各写一份**，需要统一调整时要三处同改——这是刻意的取舍，
按项目"实体类自包含"的既有口径（`Soldier` 本身就是自包含的）可接受。

> 与塔的升级链不同：塔是"**原位删旧塔、放新塔**"的换类升级（`ITowerUpgrade` 给出下一级），
> 士兵三档没有链式接口，它们是三个可独立生产的对象；"升到 2 级"在士兵侧的含义是
> **生产方改为产出 2 级兵**（见 §5.4），不是把 1 级兵原地升级。

## 3. 共同契约（继承 `Ally` / `LivingEntity`）

| 项 | 约定 |
| :--- | :--- |
| 必实现 | `findTarget(List<Enemy>)`（`Ally` 的抽象方法） |
| 近战三件套 | `attackDamage / attackCooldown / maxAttackCooldown` 与 `tryAttack()` 由 `LivingEntity` 提供，构造期经 `Ally(x, y, hp, speed, atk, cd)` 注入 |
| 碰撞拦截 | `Ally.handleEntityCollision()` 已实现：碰到敌人即锁定 `target` 并近战反击，三档共用，**子类无需重写** |
| 回防锚点 | 出生点 `(homeX, homeY)` 由各级在构造期自行记录，`target` 为空/死亡时走回待命 |
| 贴身距离 | `MELEE_RANGE = 10` 必须与 `Enemy.chaseAndAttack` 的贴身阈值一致，**三档都不得单独调**（调了会出现"追不上/抖在敌人身上"） |
| 帧步进 | 移动按 `speed * 0.016`（60fps 定步长），与敌人一致；`LivingEntity.update()` 每帧固定扣 16ms 冷却 |
| 死亡 | `onDeath()` 只做**表现**（粒子爆散）；音效由基类 `takeDamage()` 触发；**移除与结算归 `GameController`**，实体不碰列表/金币 |

## 4. 索敌与战斗流程（现状口径）

士兵拿目标有**两条通路**，目前只有第一条真正生效：

| 通路 | 状态 | 说明 |
| :--- | :--- | :--- |
| ① 碰撞拦截 | ✅ 已接线 | `GameController.processEntityCollisions()` 每帧对"敌人 × 友方"做圆碰撞 → `Enemy.onCollision` / `Ally.onCollision` → 双方互锁并近战（敌人进 `isEngaged` 追击态，停止沿路径前进） |
| ② 主动索敌 `findTarget` | ⏳ 接口在、未接线 | 当前 `GameController` 对友方只调 `update()`，**不会**主动把视野内敌人写进 `target` |

> **因此三档现在的实战表现都是"站桩拦截"**：敌人撞上来才开打，视野 90/120/150 这组数值
> 要等 A 把"每帧轮询 `findTarget` 并写入目标"接上之后才会真正发挥作用。

## 5. 使用方式

### 5.1 直接实例化（走类内默认档案）

```java
Ally a = new EliteSoldier(x, y);   // 2 级：100 / 65 / 14 / 700
Ally b = new RoyalSoldier(x, y);   // 3 级：150 / 72 / 20 / 620
```

### 5.2 生产方注入数值（推荐，与 1 级口径一致）

```java
Ally s = new EliteSoldier(x, y, hp, speed, attackDamage, attackCooldown);
```

全参构造签名与 `Soldier` 完全一致，便于把兵营的生产对象**成对替换**。

### 5.3 加入战场：只走 `GameController.addAlly(Ally)`

```java
controller.addAlly(new RoyalSoldier(x, y));   // 注入事件通道 + 进 allies 注册表 + 出兵音效
```

不要在别处自己往 `allies` 列表里塞——否则漏掉 `attachFx`（音效/粒子/飘字全哑）与出兵音效。

### 5.4 让兵营产出高级士兵（当前未接线，改动归 C/A）

`Barrack.update()` 现在写死 `new Soldier(...)`。要让 2/3 级兵营产出精英兵，推荐做法是
在 `Barrack` 抽一个工厂钩子、由 `EliteBarrack` 覆写：

```java
// Barrack
protected Ally createSoldier() {
    return new Soldier(x, y, soldierHp, soldierSpeed, soldierAttack, soldierCooldown);
}
// EliteBarrack
@Override protected Ally createSoldier() {
    return new EliteSoldier(x, y, soldierHp, soldierSpeed, soldierAttack, soldierCooldown);
}
```

> ⚠ 两条注意：
> 1. **必须在兵营侧生产**（而不是监听 `allySink` 事后替换），否则兵营自己的"上限 3/5"计数
>    与实际战场上的兵对不上；
> 2. 本文档**不改** `Barrack` / `EliteBarrack`——抽取钩子属塔负责人 C 的改动范围，
>    由 A/C 决定后再动。

### 5.5 调参位置（当前口径）

| 数值 | 位置 |
| :--- | :--- |
| 1 级士兵数值 | `Barrack` / `EliteBarrack` 的实例字段（`soldierHp` 等） |
| 2/3 级默认档案 | `EliteSoldier.DEFAULT_*` / `RoyalSoldier.DEFAULT_*`（public 常量） |
| 生产方注入值 | 构造期参数，最高优先级 |

> 后续若按《数值配置 JSON 化规范》二期把"每类单位数值"搬进 `config/balance.json`，
> 以该规范为准统一改口径，本文档 §1 表格届时同步更新。

## 7. 新增一档士兵的扩展流程

1. 在 `model/ally/` 新建 `XxxSoldier extends Ally`（**不要**继承 `Soldier`/`EliteSoldier`，保持三档并列）；
2. 照抄三件套骨架：`VISION_RANGE` / `MELEE_RANGE(=10)` / `RETURN_EPSILON` + `homeX/homeY`
   + `findTarget` / `move` / `returnHome` / `onDeath` / `render`；
3. 追加贴图 key（`AssetKey`）与 `render` 回退色块；
4. 由生产方构造 → `GameController.addAlly(...)` 上战场；
5. 需要动画再补 `assets/animations/allies/xxx_soldier.json` 并在 `Main` 登记。

## 9. 范围红线

- **不改 1 级 `Soldier` 的现有行为与数值口径**（它仍是 `Barrack` 生产的那一个，且三级不靠它派生）；
- **不改 `Barrack` / `EliteBarrack` 的生产逻辑**：本文档只说明"要接怎么接"，改动归 C/A；
- **三档互不继承是刻意选择**：不要为"省代码"把 3 级改成继承 2 级，也不要给 `Soldier` 加
  供精英档覆写的钩子——一旦加钩子，三档又会耦合回继承链；
- 不改 `Ally` / `LivingEntity` 的公共契约（`MELEE_RANGE` 一致、死亡不碰列表金币等）。
