> 归属：友方单位开发（实体 B）；兵营侧的产出接线归 C / A

## 1. 三档士兵一览

| 等级 | 类 | HP | 速度 | 攻击 | 冷却 | 索敌视野 | 体型 | 显示名 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 级 | `Soldier` | 兵营注入 | 兵营注入 | 兵营注入 | 兵营注入 | 类常量（最小） | `sizes.json` 的 `Soldier` | 士兵 |
| 2 级 | `EliteSoldier` | 兵营注入 | 兵营注入 | 兵营注入 | 兵营注入 | 类常量（中） | `sizes.json` 的 `EliteSoldier` | 精英士兵 |
| 3 级 | `RoyalSoldier` | 兵营注入 | 兵营注入 | 兵营注入 | 兵营注入 | 类常量（最大） | `sizes.json` 的 `RoyalSoldier` | 皇家卫士 |

- **两套数值别混**：
  - 「兵营注入值」= **实际战场数值**，来自 `config/tower.json` 的 `barrackL{1,2,3}.soldierHp / soldierSpeed / soldierAttack / soldierCooldown`，由兵营在 `createSoldier()` 时传入（见 §5.4）；
  - 「类内默认档案」= `EliteSoldier.DEFAULT_*` / `RoyalSoldier.DEFAULT_*`（public 常量），**仅在直接 `new XxxSoldier(x, y)` 时兜底，不参与兵营生产**。`Soldier` 无默认档案，必须注入。
  - 三档的默认档案**互不相同**（等级越高越强），但**兵营产出时一律覆盖为注入值**——同一兵营等级产出的三档兵数值相同，差异体现在视野、体型与等级标记。
- **视野是类的固有属性**，不因注入而变（三档依次递增，写在各类的 `VISION_RANGE` 常量里）。
- **体型由 `assets/sizes.json` 按类名驱动**（见 §6），类内不写死。

## 2. 分级方式：三档并列，互不继承（重要）

三档士兵都是 `Ally` 的**直接子类**，彼此没有继承关系：

```
Ally（抽象：索敌策略 + 对敌碰撞反应）
├── Soldier        1 级
├── EliteSoldier   2 级   ← 不继承 Soldier
└── RoyalSoldier   3 级   ← 不继承 EliteSoldier
```

**为什么这么分**：每档的数值、视野、体型、渲染各自独立，改 2 级不会波及 1/3 级；代价是索敌/追击/回防三段逻辑**每档各写一份**，需要统一调整时要三处同改——这是刻意的取舍。

> 与塔的升级链不同：塔是「**原位删旧塔、放新塔**」的换类升级（`ITowerUpgrade` 给出下一级）；
> 士兵三档没有链式接口，它们是三个可独立生产的对象；「升到 2 级」在士兵侧的含义是
> **生产方改为产出 2 级兵**（见 §5.4），不是把 1 级兵原地升级。

## 3. 共同契约（继承 `Ally` / `LivingEntity`）

| 项 | 约定 |
| :--- | :--- |
| 必实现 | `findTarget(List<Enemy>)`（`Ally` 的抽象方法） |
| 近战三件套 | `attackDamage / attackCooldown / maxAttackCooldown` 与 `tryAttack()` 由 `LivingEntity` 提供，构造期经 `Ally(x, y, hp, speed, atk, cd)` 注入 |
| 碰撞拦截 | `Ally.handleEntityCollision()` 已实现：碰到敌人即锁定 `target` 并近战反击，三档共用，**子类无需重写** |
| 回防守岗位 | 驻守点 + 个人站岗散布（`STAND_SPREAD`×个人方位角）：`target` 为空/死亡时走回待命；未注入驻守点（或路径缺失）时退化为出生点。**三档一致** |
| 驻守点 | 由**能力接口 `model.ally.IGuardPoint`** 暴露：装配层 `GameController.addAlly` 注入「离兵营最近的路径点」（未注入时实现方自持默认值＝出生点）。三档均实现该接口；**装配层按接口判定、不按兵种判定**（见 §8） |
| 贴身距离 | `ATTACK_RING + RETURN_EPSILON`（8+2=10）必须与 `Enemy.chaseAndAttack` 的停步阈值（**硬编码在 `Enemy.java` 的 `10`**）一致，**三档都不得单独调**（调了会出现「追不上 / 抖在敌人身上」）；渲染层 `UnitPoseResolver.MELEE_DIST` 是同一数值的第三份副本，动任一处需三处同改 |
| 帧步进 | 移动按 `speed * 0.016`（60fps 定步长），与敌人一致；`LivingEntity.update()` 每帧固定扣 16ms 冷却 |
| 死亡 | `onDeath()` 只做**表现**（粒子爆散）；音效由基类 `takeDamage()` 触发；**移除与结算归 `GameController`**，实体不碰列表/金币 |
| 命中飘字 | `Ally.tryAttack()` 覆写：命中判定沿用基类，命中后调 `Ally.onHit(target)`——与 `Bomb.onHit` 同一套 `fxText` 写法（目标头顶、白色、`-伤害`）。三档共用；近战**只做飘字**，不加粒子/震屏/命中音 |
| 叠加后钩子 | `Ally.renderPostAnim(gc)` 默认空；精英兵种覆写它画等级标记（金环/盔缨），由渲染层在动画帧叠加之后调用 |

## 4. 索敌与战斗流程

士兵拿目标有**两条通路**，两条都已接线：

| 通路 | 状态 | 说明 |
| :--- | :--- | :--- |
| ① 碰撞拦截 | ✅ 已接线 | `GameController.processEntityCollisions()` 每帧对「敌人 × 友方」做圆碰撞 → `Enemy.onCollision` / `Ally.onCollision` → 双方互锁并近战（敌人进 `isEngaged` 追击态，停止沿路径前进） |
| ② 主动索敌 | ✅ 已接线 | `GameController` 友方循环：`a.engage(a.findTarget(enemies))` → 视野内最近敌人写进 `target`，随后 `a.update()` 驱动移动（`Ally.engage` 只在无目标/目标已死时接手，防逐帧换目标抖动） |

> **接线的意义**：士兵出生在兵营（塔位）处，而塔位离路径中线有一段距离；碰撞触发要求距离小于双方半径和——
> **只靠碰撞的话敌人撞不到士兵，士兵会一直站桩不动**。有了主动索敌，士兵才会主动出击视野内敌人、目标死亡后走回待命点。
>
> ⚠️ 视野是类常量、覆盖不到最远的塔位（`maps/default/spots.json` 中最远塔位距路径中线约 97px，
> 已超出 1 级士兵视野）；建在那里的兵营，产出的低阶士兵仍会站着不动——要覆盖需调大 `Soldier.VISION_RANGE`，属改数值，另议。

## 5. 使用方式

### 5.1 直接实例化（走类内默认档案）
```java
Ally a = new EliteSoldier(x, y);   // 2 级：取 EliteSoldier.DEFAULT_*
Ally b = new RoyalSoldier(x, y);   // 3 级：取 RoyalSoldier.DEFAULT_*
```

### 5.2 生产方注入数值（推荐，与 1 级口径一致）
```java
Ally s = new EliteSoldier(x, y, hp, speed, attackDamage, attackCooldown);
```
全参构造签名与 `Soldier` 完全一致，便于把兵营的生产对象**成对替换**。

### 5.3 加入战场：只走 `GameController.addAlly(Ally)`
```java
controller.addAlly(new RoyalSoldier(x, y));   // 注入事件通道 + 进 allies 注册表 + 出兵音效
```
不要在别处自己往 `allies` 列表里塞——否则漏掉事件通道注入（音效/粒子/飘字全哑）与出兵音效。

### 5.4 兵营产出高级士兵

`Barrack` 抽出工厂钩子 `createSoldier()`，`update()` 经它取兵；2/3 级兵营只**覆写该钩子**换兵种：

```java
// Barrack（默认产 1 级 Soldier；数值取本兵营等级字段）
protected Ally createSoldier() {
    return new Soldier(x, y, soldierHp, soldierSpeed, soldierAttack, soldierCooldown);
}
// EliteBarrack（2 级）
@Override protected Ally createSoldier() {
    return new EliteSoldier(x, y, soldierHp, soldierSpeed, soldierAttack, soldierCooldown);
}
// MasterBarrack（3 级）
@Override protected Ally createSoldier() {
    return new RoyalSoldier(x, y, soldierHp, soldierSpeed, soldierAttack, soldierCooldown);
}
```

> 要点：
> 1. **必须在兵营侧生产**（而不是监听 `allySink` 事后替换），否则兵营自己的「上限计数」与实际战场上的兵对不上——本实现即在 `Barrack.update()` 内调用钩子；
> 2. **数值一律取兵营等级字段**（构造期由 `barrackL*` 键读入），士兵类的 `DEFAULT_*` 不参与；
> 3. **返回类型为 `Ally`**：三档士兵是 `Ally` 的并列子类（§2），故钩子用 `Ally` 而非 `Soldier`；
> 4. 新增兵营/兵种时**只需新增子类重写 `createSoldier()`**，不必改 `Barrack.update()` 的生产流程。

### 5.5 调参位置

| 数值 | 位置 |
| :--- | :--- |
| 兵营产出的士兵数值（战场实际值） | `config/tower.json` 的 `barrackL1/L2/L3` 之 `soldierHp / soldierSpeed / soldierAttack / soldierCooldown`（改后重启生效） |
| 2/3 级直接实例化的默认档案 | `EliteSoldier.DEFAULT_*` / `RoyalSoldier.DEFAULT_*`（public 常量） |
| 生产方注入值 | 构造期参数，最高优先级 |
| 视野 / 贴身距离 / 拴绳 / 站岗散布 | 各类的 `VISION_RANGE` / `ATTACK_RING` / `RETURN_EPSILON` / `LEASH_RANGE` / `STAND_SPREAD` 等类常量（**不纳入 JSON**，属行为手感参数）。**三档取值**：视野 90/120/150；拴绳 150/150/**180**（3 级 +30，消除"能锁定却走不到"的抖动带）；站岗散布 18/**27**/**30**（≈3/4 体型，防站立重叠）；环形半径 8 与就位容差 2 三档同值 |

## 6. 素材与动画接入

| 项 | 契约 |
| :--- | :--- |
| 贴图 key | `AssetKey.SOLDIER` / `ELITE_SOLDIER` / `ROYAL_SOLDIER` → `assets/<snake_case>.png`（**缺图自动回退色块，不报错**，无需等素材） |
| 行为动画 | 三档**各有独立动画表**：`assets/animations/allies/{soldier,elite_soldier,royal_soldier}.json`，由 `Main` 分别登记（`registerUnitAnimation`）。近战时自动切 `attack` 模式播挥砍（判定见 `UnitPoseResolver`）。`royal_soldier.json` 目前**无 `death` 模式**，死亡时保持上一姿态（非报错） |
| 打击动作 | 帧图放在 `assets/allies/<单位>/attack_*.png`，由各自 JSON 的 `attack` 模式引用；等级差异由**体型 + 标记**体现 |
| 等级标记 | 动画帧会画满整个身体框，故标记改由 `Ally.renderPostAnim` 在帧之上补画；`render()` 里的色块回退保持原样 |
| 命中飘字 | 由 `Ally.tryAttack` 触发 `fxText.showFloatingText(...)`；飘字层实现见 `GameView.showFloatingText` |
| 尺寸 | 由 `assets/sizes.json` 按类名驱动，类内**不写死** |

**无素材时的回退外观**：1 级蓝圆身 + 深蓝边；2 级蓝圆身 + 金色精英环 + 肩章金星；3 级深蓝圆身 + 加粗金环 + 肩章金星 + 红色盔缨。

> 抗眩晕/受击闪烁等表现三档一致；血条宽度随体型自动变化。
> 等级标记由 `renderPostAnim` 画在动画帧之上，所以动画播放时标记依然可见。

## 7. 新增一档士兵的扩展流程

1. 在 `model/ally/` 新建 `XxxSoldier extends Ally`（**不要**继承 `Soldier`/`EliteSoldier`，保持三档并列）；
2. 照抄骨架：`VISION_RANGE` / `ATTACK_RING` / `RETURN_EPSILON` / `LEASH_RANGE` / `STAND_SPREAD` / `bearingAngle` + `guardX/guardY`（驻守点，未注入时=出生点）+ `findTarget` / `move` / `returnHome` / `onDeath` / `render`，并 `implements IGuardPoint`（否则装配层不会注入驻守点，见 §8）；
3. 追加贴图 key（`AssetKey`）与 `render` 回退色块；需要在动画帧之上保留等级标记就覆写 `renderPostAnim`；
4. 在 `assets/sizes.json` 的 `entities` 里加一条 `"XxxSoldier": {"width":W,"height":H}`（**尺寸不写进代码**）；
5. 由生产方构造 → `GameController.addAlly(...)` 上战场；
6. 需要动画再补 `assets/animations/allies/xxx_soldier.json` 并在 `Main` 登记。

## 9. 范围红线

- **不改 1 级 `Soldier` 的现有行为与数值口径**（它仍是 `Barrack` 生产的那一个，且三级不靠它派生）；
- **`Barrack` 的生产流程保持通用**：兵种差异只经 `createSoldier()` 钩子，`update()` 的槽位/计时/上限逻辑不因兵种而变；不要为「省事」在 `update()` 里按等级分支产兵；
- **三档互不继承是刻意选择**：不要为「省代码」把 3 级改成继承 2 级，也不要给 `Soldier` 加供精英档覆写的钩子——一旦加钩子，三档又会耦合回继承链；
- `Ally` 上现有两个**表现类**钩子（`tryAttack` 命中飘字、`renderPostAnim` 等级标记），它们只影响「看起来怎样」，**不得往里面塞战斗逻辑**；
- 不改 `LivingEntity` 的既有语义（死亡不碰列表金币等）。
