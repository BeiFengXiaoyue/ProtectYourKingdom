# 敌人行为动画渲染层设计（外部推导 + 叠加渲染）

> 状态：设计稿（未实现）
> 前置：`util/AnimTable`、`util/AnimLibrary`、`util/AnimEditorTool`（JSON 动画表 + 可视化编辑器）已就绪；
> 本文描述“如何在不改敌人类的前提下，把配置好的行为动画真正渲染到游戏里”。

---

## 1. 背景与约束

- **敌人(Enemy 及其子类)已写死**：不改其继承关系、字段、`render()` 内部实现；
- 行为动画 JSON 已存在：`src/main/resources/assets/animations/<敌人名>.json`
  ```json
  { "name": "normal_enemy", "interval": 6,
    "modes": { "idle": [...], "walk": [...], "attack": [...] } }
  ```
- 模式键当前由编辑器模板默认给出 `idle / walk / attack`（契约未固化，本文按“标准键”处理，并允许扩展）。
- 敌人自身**没有**“当前行为模式”字段 —— 因此需要**外部推导**。

## 2. 核心思路：模式判定外置

敌人的“真实行为”已经体现在它的公开状态上，动画层只做**只读观察**，敌人零改动。

| 判定条件（每帧，按优先级从上到下） | 推导出的模式 | 依据 |
| --- | --- | --- |
| 死亡 `!isAlive()`（可选） | `death` | `LivingEntity.isAlive()` |
| 眩晕 `isStunned()` | `idle` | 眩晕时 LivingEntity.update 不调 move，不移动不攻击 |
| 拦截贴身 `isEngaged() && 目标距离 ≤ 10` | `attack` | `Enemy.chaseAndAttack`：`dist>10` 才位移，贴身时站桩 `tryAttack`（阈值 10 与敌人类一致）|
| 本帧有位移（与上一帧坐标差 > 0） | `walk` | 沿路径 / 追击位移中 |
| 其余（待命/无路可走） | `idle` | 兜底 |

- 状态全部来自公开 getter：`getX/getY/isStunned/isAlive/isEngaged/getEngagedTarget/getCurrentHp/getMaxHp`；
- 跨帧位移由渲染层按“敌人实例 → 上帧坐标”自行记录，不需要敌人记忆。

## 3. 组件设计

### 3.1 `util/EnemyPoseResolver`（行为解析器，纯规则）
- 输入：某敌人的公开状态 + 本帧位移量；
- 输出：模式名（`idle/walk/attack`…）；
- 规则做成**有序可增删**的判定链（便于扩展，如“半血狂暴”→注册 `enrage` 判定，读 `getCurrentHp/getMaxHp`）。

### 3.2 `util/EnemyAnimator`（渲染叠加层，按敌人实例有状态）
- `register(String enemyClassName, String descriptorResource)`：Main 接线时把“某敌人 → 它的 JSON 资源地址”登记；
- 内部按 `IdentityHashMap<Enemy, State>` 记录：上一帧坐标、当前模式、tick；
- `overlay(GraphicsContext gc, Enemy e)`：**在 GameView 敌人 `render()` 之后调用**：
  1. 用 `EnemyPoseResolver` 得到当前模式；
  2. 查该敌人 AnimTable 的 `modes[模式]`；缺键/缺帧图 → **返回（无操作，敌人原样显示）**；
  3. 帧推进：`tick / interval` 决定当前帧序号（60 tick/s）；
  4. 取图（`Assets.get("/assets/" + 相对路径)`）以 `(e.getX(), e.getY(), e.getWidth(), e.getHeight())` 中心叠加绘制。
- 叠加区域=敌人身体区；敌人自绘的头顶血条位于身体上方，不受影响。

### 3.3 渲染接线（只改 GameView / Main，不动敌人）
- `GameView`：持有 `EnemyAnimator`；敌人绘制循环改为
  ```java
  for (Enemy e : stateReader.getEnemies()) {
      e.render(gc);
      animator.overlay(gc, e);
  }
  ```
- `Main` 注册示例：
  ```java
  view.registerEnemyAnimation("NormalEnemy", "/assets/animations/normal_enemy.json");
  ```

## 4. 数据 → 渲染时序

```
Main 注册 敌人名→JSON 地址
   ↓ AnimTable.loadFromClasspath（带缓存）
每帧 GameView.draw()
   对每只 Enemy：
     EnemyPoseResolver.resolve(e, 位移)  → 模式名
     AnimTable.modes[模式] 存在？ ——否→ 跳过叠加（保留原渲染）
     是→ Animator 按 interval 推进 tick → 取当前帧图
         → Assets 按路径加载 → gc.drawImage 叠加在敌人身体
```

## 5. 扩展性

- **新增一种行为** = ① 给该敌人 JSON 加一个 modes 键并配帧；② 在 `EnemyPoseResolver` 注册一条新判定规则（可只对特定敌人类名生效）；
- 模式命名建议统一小写下划线（`idle/walk/attack/enrage/death`）；
- 缺素材/缺键一律回退，不阻塞运行。

## 6. 验收标准

1. 无任何帧图 / 无 JSON 时：敌人渲染与现在**完全一致**（回归无损）；
2. 放好 idle/walk/attack 帧图后：敌人沿路走→轮播 `walk`；眩晕/站立→`idle`；被拦贴身近战→`attack`；
3. 帧切换节奏由 `interval` 控制；速度/眩晕等状态不被改动。
