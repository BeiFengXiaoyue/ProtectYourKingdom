# 单位行为动画渲染层设计（外部推导 + 叠加渲染）

> 状态：设计稿（未实现）
> 适用范围：**所有活体单位**（敌人 Enemy、友方 Ally/士兵等）。本文以敌人为样例描述，
> 机制与阵营无关，友方/士兵按同一契约接入。
> 前置：`util/AnimTable`、`util/AnimLibrary`、`util/AnimEditorTool`（单位行为动画 JSON + 可视化编辑器）已就绪。
> 若后续实现仍按“敌人优先”，可将组件暂时命名为 EnemyPoseResolver/EnemyAnimator，但接口语义按“单位”通用。

---

## 1. 背景与约束

- **活体单位类（Enemy/Ally 及其子类）已写死**：不改其继承关系、字段、`render()` 内部实现；
- 行为动画 JSON 已存在：`src/main/resources/assets/animations/<单位名>.json`
  ```json
  { "name": "normal_enemy", "interval": 6,
    "modes": { "idle": [...], "walk": [...], "attack": [...] } }
  ```
- 模式键当前由编辑器模板默认给出 `idle / walk / attack`（契约未固化，本文按“标准键”处理，并允许扩展）；
- 单位**自身没有**“当前行为模式”字段 —— 因此需要**外部推导**。

## 2. 核心思路：模式判定外置

单位的“真实行为”体现在它的公开状态上，动画层只做**只读观察**，单位代码零改动。

| 判定条件（每帧，按优先级从上到下） | 推导出的模式 | 依据 |
| --- | --- | --- |
| 眩晕 `isStunned()` | `idle` | 眩晕时 LivingEntity.update 不调 move，不移动不攻击 |
| 近战贴身攻击中（敌人：`isEngaged()` 且与目标距离 ≤10；友方近战同理） | `attack` | 敌人阈值 10 与 `Enemy.chaseAndAttack` 一致；友方规则另行注册 |
| 本帧有位移（与上一帧坐标差 > 0） | `walk` | 移动中（沿路/追击/巡逻） |
| 其余（待命/无位移） | `idle` | 兜底 |

- 状态全部来自公开 getter（LivingEntity 级：`getX/getY/isStunned/isAlive/getCurrentHp/getMaxHp` + 各方攻击状态 getter）；
- 跨帧位移由渲染层按“单位实例 → 上帧坐标”自行记录，单位无需记忆。

## 3. 组件设计

### 3.1 `util.UnitPoseResolver`（行为解析器，纯规则）
- 输入：某单位的公开状态 + 本帧位移量；
- 输出：模式名（`idle/walk/attack`…）；
- 规则做成**按单位类型注册、可增删**的判定链（扩展：半血狂暴→`enrage`、死亡→`death` 等，读 `getCurrentHp/getMaxHp`）。

### 3.2 `util.UnitAnimator`（渲染叠加层，按单位实例有状态）
- `register(String unitClassName, String descriptorResource)`：Main 接线时把“某单位 → 它的 JSON 资源地址”登记；
- 内部按 `IdentityHashMap<LivingEntity, State>` 记录：上一帧坐标、当前模式、tick；
- `overlay(GraphicsContext gc, LivingEntity unit)`：**在 GameView 该单位 `render()` 之后调用**：
  1. 用 `UnitPoseResolver` 得到当前模式；
  2. 查该单位 AnimTable 的 `modes[模式]`；缺键/缺帧图 → **返回（无操作，单位原样显示）**；
  3. 帧推进：`tick / interval` 决定当前帧序号（60 tick/s）；
  4. 取图（`Assets.get("/assets/" + 相对路径)`）以 `(getX(), getY(), getWidth(), getHeight())` 中心叠加绘制。
- 叠加区域=单位身体区；单位自绘的头顶血条位于身体上方，不受影响。

### 3.3 渲染接线（只改 GameView / Main，不动单位类）
- `GameView`：持有 `UnitAnimator`；敌/友绘制循环各加一行
  ```java
  // 敌人
  for (Enemy e : stateReader.getEnemies()) { e.render(gc); animator.overlay(gc, e); }
  // 友方
  for (Ally a : stateReader.getAllies())   { a.render(gc); animator.overlay(gc, a); }
  ```
- `Main` 注册示例：
  ```java
  view.registerUnitAnimation("NormalEnemy", "/assets/animations/normal_enemy.json");
  view.registerUnitAnimation("Soldier",     "/assets/animations/soldier.json");
  ```

## 4. 数据 → 渲染时序

```
Main 注册 单位类名→JSON 地址
   ↓ AnimTable.loadFromClasspath（带缓存）
每帧 GameView.draw()
   对每个单位（敌人/友方）：
     UnitPoseResolver.resolve(unit, 位移)  → 模式名
     AnimTable.modes[模式] 存在？ ——否→ 跳过叠加（保留原渲染）
     是→ UnitAnimator 按 interval 推进 tick → 取当前帧图
         → Assets 按路径加载 → gc.drawImage 叠加在单位身体
```

## 5. 扩展性

- **新增一种行为** = ① 给该单位 JSON 加一个 modes 键并配帧；② 给该单位类型注册一条新判定规则；
- 模式命名建议统一小写下划线（`idle/walk/attack/enrage/death`）；
- 缺素材/缺键一律回退，不阻塞运行；敌/友共用同一套数据格式与渲染层。

## 6. 验收标准

1. 无任何帧图 / 无 JSON 时：所有单位渲染与现在**完全一致**（回归无损）；
2. 敌人：沿路走→`walk`；眩晕/站立→`idle`；被拦贴身近战→`attack`；
3. 友方（士兵接入后）：移动→`walk`、待命→`idle`、近战→`attack`；
4. 帧切换节奏由 `interval` 控制；状态（速度/眩晕等）不被改动。
