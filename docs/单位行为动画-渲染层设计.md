# 单位行为动画渲染层设计（外部推导 + 叠加渲染）

> 状态：设计稿（未实现）
> 适用范围：**敌人 Enemy / 友方 Ally(士兵) / 防御塔 Tower** 三类。活体按“位移/战斗”判定，
> 塔为常时 `idle` 循环（本轮不动塔基类，暂不分“开火帧”）。
> 前置：`util/anim/AnimTable`、`util/anim/AnimLibrary`、`util/editor/AnimEditorTool`（三类通用 JSON 动画 + 编辑器）已就绪。

---

## 1. 背景与约束

- **单位类（Enemy/Ally/Tower 及其子类）已写死**：不改其继承关系、字段、`render()` 内部实现；
- 动画表 JSON：`src/main/resources/assets/animations/{enemies,allies,towers}/<单位名>.json`
  ```json
  { "kind": "enemies", "name": "normal_enemy", "interval": 6,
    "modes": { "idle": [...], "walk": [...], "attack": [...] } }
  ```
  帧路径相对 `assets/`，形如 `"enemies/normal_enemy/walk_0.png"`；
- 模式键：敌人/友方模板 `idle/walk/attack`；塔模板 `idle`（可扩展）；
- 单位**自身没有**“当前行为模式”字段 —— 需要**外部推导**。

## 2. 核心思路：模式判定外置

单位的“真实行为”体现在公开状态上，动画层只做**只读观察**，单位代码零改动。

| 类别 | 判定（每帧） | 模式 |
| --- | --- | --- |
| 敌人/友方 | 眩晕 `isStunned()` | `idle` |
| 敌人/友方 | 近战贴身攻击中（敌人 `isEngaged()` 且目标距离≤10；友方近战同理） | `attack` |
| 敌人/友方 | 本帧有位移（与上帧坐标差>0） | `walk` |
| 敌人/友方 | 兜底（待命/无位移） | `idle` |
| 防御塔 | 无条件 | `idle`（常时循环；如需开火帧，未来给 Tower 加只读指示后扩展） |

- 状态来自公开 getter（坐标/眩晕/存活/攻击状态等）；塔只用 `getX/getY/getWidth/getHeight`；
- 跨帧位移由渲染层按“单位实例 → 上帧坐标”自行记录。

## 3. 组件设计

### 3.1 `util.anim.UnitPoseResolver`（行为解析器，纯规则）
- 输入：某单位的公开状态 + 本帧位移量（塔恒 idle）；
- 输出：模式名；规则做成**按单位类型注册、可增删**的判定链。

### 3.2 `util.anim.UnitAnimator`（渲染叠加层，按单位实例有状态）
- `register(String kind, String unitClassName, String descriptorResource)`：Main 接线登记
  “单位类别 + 类名 → JSON 资源地址”；
- 内部按实例记录：上一帧坐标、当前模式、tick；
- `overlay(GraphicsContext gc, GameObject unit)`：在 GameView 该单位 `render()` 之后调用：
  1. `UnitPoseResolver` 得模式；
  2. 查该单位 AnimTable `modes[模式]`；缺键/缺帧 → 无操作（原样显示）；
  3. 按 `interval` 推进 tick 取帧；
  4. `Assets.get("/assets/"+相对路径)` 以 `(x,y,w,h)` 中心叠加。

### 3.3 渲染接线（只改 GameView / Main，不动单位类）
- `GameView`：敌/友/塔绘制循环各加 `render(gc); animator.overlay(gc, unit);`
  ```java
  for (Tower t : stateReader.getTowers())    { t.render(gc); animator.overlay(gc, t); }
  for (Ally  a : stateReader.getAllies())    { a.render(gc); animator.overlay(gc, a); }
  for (Enemy e : stateReader.getEnemies())   { e.render(gc); animator.overlay(gc, e); }
  ```
- `Main` 注册示例：
  ```java
  view.registerUnitAnimation("enemies", "NormalEnemy", "/assets/animations/enemies/normal_enemy.json");
  view.registerUnitAnimation("allies",  "Soldier",     "/assets/animations/allies/soldier.json");
  view.registerUnitAnimation("towers",  "ArrowTower",  "/assets/animations/towers/arrow_tower.json");
  ```

## 4. 数据 → 渲染时序

```
Main 注册 (kind, 单位类名→JSON 地址)
   ↓ AnimTable.loadFromClasspath（带缓存）
每帧 GameView.draw()
   对每个单位（敌/友/塔）：
     UnitPoseResolver.resolve(unit, 位移)  → 模式名
     AnimTable.modes[模式] 存在？——否→ 跳过叠加（保留原渲染）
     是→ UnitAnimator 按 interval 推进 tick → 取当前帧图
         → Assets 按路径加载 → gc.drawImage 叠加在单位身体
```

## 5. 扩展性

- **新增一种行为** = ① 给该单位 JSON 加 modes 键并配帧；② 给该单位类型注册一条判定规则；
- 模式命名小写下划线（`idle/walk/attack/enrage/death/fire…`）；
- 缺素材/缺键一律回退；敌/友/塔共用同一套数据格式与渲染层。

## 6. 验收标准

1. 无任何帧图 / 无 JSON：所有单位渲染与现在**完全一致**（回归无损）；
2. 敌人：走→`walk`；站/眩晕→`idle`；贴身近战→`attack`；
3. 友方（士兵接入）：移动→`walk`、待命→`idle`、近战→`attack`；
4. 防御塔：持续 `idle` 帧循环（如旋转/摆动）；若未来增加“开火帧”，需先给 Tower 暴露只读开火指示再扩展规则。
