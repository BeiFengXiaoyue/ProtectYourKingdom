# 《王国保卫战》接口契约与抽象类说明

> 版本：现行版（随代码同步维护）
> 说明：本文档是各模块**并行开工的契约依据**。所有接口坚持**单一职责、无 default 方法**；未注入实现时由 `util/fx/FxNop` 提供空实现兜底，保证任何阶段运行不抛 NPE。

---

## 1. 分层总览与分工矩阵

包结构（均在 `com.kingdom.game.*` 下）：

```
controller    控制层与接口契约（GameController、WaveManager、全部接口）
model         领域模型（抽象类/枚举/数据类/GameState）
model/enemy   敌人（Enemy 及 Normal/Fast/Tank/Boss）
model/ally    友方（Ally 及 Soldier/EliteSoldier/RoyalSoldier）
model/tower   防御塔（Tower 及三族三级）
model/projectile  投射物（Projectile/Arrow/Bomb）
view          UI 层（Main、GameView、HUD、TowerBuildMenu、TowerDetailPanel）
config        数值配置（GameConfig）
util          工具根（按功能子包，不直接放类：map/anim/editor/asset/audio/fx/json/balance）
              balance = 数值文件 config/balance.json 与 config/tower.json 的读写（见 §5.1）
resources     assets/*.png 素材目录（Maven 打包为 classpath:/assets/）
```

| 分工 | 主要产出 | 只依赖（契约） | 禁止依赖 |
|---|---|---|---|
| 防御塔（C） | Tower 具体子类、塔数值与渲染（`attack()` 生成投射物并 `fire()`，不写投射物本体） | `Tower` 抽象类、`TowerSpec`、`GameController.registerTower(...)`、`ITowerSound` | 禁止反向改 GameController 实现 |
| 实体（B） | 敌人 / 投射物 / 士兵具体类（含 `Arrow/Bomb` 的 `onHit`/`render`） | `LivingEntity/Enemy/Ally/Projectile` 抽象类、`Faction/ICollidable/AssetKey`、`ICombatSound` | 禁止 import GameController 具体类 |
| 素材与音效（E） | 贴图 png、音效事件实现 | `AssetKey` + `Assets`、9 个音效/视觉接口 | 不改任何逻辑代码 |
| UI 与控制层交互（D） | Main、GameView、HUD、建塔栏、详情面板 | 控制器层 **17 个接口** | 不 import model 具体实现做分支 |

**数据流规则**：UI 只通过接口调后端；控制层负责「每帧驱动 + 注册表 + 结算 + 移除」；实体只负责自身 update/render/表现，涉及金币/生命/列表变动的**唯一结算者 = GameController**。

### 1.1 模块归属

| 模块 / 文件 | 归属 |
| :--- | :--- |
| `model/enemy/*`、`model/ally/*`、`model/projectile/*`（含 `Arrow`/`Bomb` 的 fly/onHit/render 实化） | **B（实体）** |
| `model/tower/*`（索敌 + `attack()` 生成投射物并交给 `projectileSink`） | **C（塔）** |
| 抽象基类、controller 接口、`GameController`、`WaveManager`、`GameConfig` 读通道 | **A（集成/架构）** |
| `view/*`（GameView / HUD / TowerDetailPanel / 建塔菜单）、`Main` | **D（UI）** |
| `util/asset/Assets` 贴图、音效接口实现（`util/audio/SoundManager`） | **E（素材/音效）** |
| `config/balance.json`、`config/tower.json` 取值与 `BalanceEditorTool` | **F（测试/数值）** |

### 1.2 范围红线（不做清单）

- **不新增第二套数值 / 尺寸 / 波次通道**：数值唯一源文件 = `config/balance.json`（塔数值 = `config/tower.json`），走势以《数值配置 JSON 化规范》§0 为准。
- 不改 `maps/**` 的路径与塔位语义、不改 `assets/animations/**` 的动画数据格式。
- **不引入第三方 JSON 库**（继续用 `util/json/MiniJson`）。
- 不改 `LivingEntity` 的既有语义：`MELEE_RANGE` 一致、死亡不碰列表金币。
- 塔的「换类升级」架构（`ITowerUpgrade` + 原位替换）不推翻。
- 三档士兵「互不继承」的取舍不推翻（不把 3 级改成继承 2 级）。
- **公共抽象类 / 接口 / `GameController` / `GameConfig` 改动需集成负责人过手**，其余模块交付 diff 后合入。

### 1.3 红线：模块间三条硬约束

1. **投射物本体归 B**：`Arrow`/`Bomb` 的 `onHit()`（命中扣血/AOE）与 `render()` 由实体负责人实化；塔的 `attack()` 只负责生成投射物并 `fire()`（经 `projectileSink`），不写投射物本体。
2. **禁止「TODO 空骨架」当作完成交付**：每个具体类核心行为（移动/命中/渲染/索敌/攻击）必须可用；贴图与音效允许先用色块 / `FxNop` 兜底，核心逻辑不能留空。
3. **任何实体 / 素材类不得 `import com.kingdom.game.controller.GameController`**（可依赖其接口）；金币 / 生命 / 注册表结算一律走控制层。

## 2. 接口契约

接口一律位于 `controller` 包（`ICollidable`、`ITowerUpgrade`、`IChainShot`、`IBurnEffect`、`IHealAura` 例外——属 model 层能力契约，由实体/塔类实现）。

### 2.1 UI → 控制层（交互入口）

#### `ITowerBuilder`（建塔操作）
| 方法 | 说明 |
|---|---|
| `boolean placeTower(double x, double y, TowerType type)` | 尝试建造；返回是否成功（失败经 IStatusObserver 推送原因） |
| `void upgradeTower(Tower tower)` | 升级选中塔（内部校验金币；**升级 = 原位换更高等级塔类**，见 §3.5.1） |
| `void sellTower(Tower tower)` | 出售，返还 50% 投入 |

调用方：鼠标点击处理器 / 塔详情面板。实现方：GameController。

#### `IWaveStarter`（波次）
`void startNextWave();` / `boolean canStartNextWave();`
调用方：「开始波次」按钮。实现方：GameController。

#### `IGameLoop`（主循环）
`void update(long nanoTime);` 由 GameView 的 AnimationTimer 每帧调用。

#### `IGameStateReader`（只读查询，供 UI 拉取渲染数据）
| 方法 | 说明 |
|---|---|
| `int getCurrentGold() / getCurrentLives() / getCurrentWave() / getTotalWaves()` | 状态 |
| `long getNextWaveCountdownMs()` / `int getEarlyStartBonus()` | 波间倒计时 / 提前开始奖励 |
| `List<Enemy> getEnemies()` / `List<Tower> getTowers()` / `List<Projectile> getProjectiles()` / `List<Ally> getAllies()` | 四类实体列表（渲染用） |
| `List<TowerSpec> getTowerSpecs()` | 可建造塔目录（建塔菜单数据源） |
| `boolean isGameOver()` / `boolean isVictory()` | 胜负查询 |
| `List<LevelInfo> getLevels()` / `getLevelCount()` / `getCurrentLevel()` / `getCurrentLevelIndex()` / `getCurrentLevelKey()` / `hasNextLevel()` / `hasPrevLevel()` | 关卡只读查询（切关**动作**见 `ILevelSwitcher`） |

实现方：GameController。调用方：GameView / HUD / 建塔栏 / 详情面板。

#### `ILevelSwitcher`（关卡切换，动作）
`boolean switchLevel(String key);` / `boolean switchLevelAt(int index);` / `boolean goNextLevel();` / `boolean goPrevLevel();` / `boolean restartLevel();`

调用方：GameView 的「下一关 / 上一关 / 重开本关」按钮。实现方：GameController。
与 `IWaveStarter` 对称——本接口只放**动作**；关卡只读查询走 `IGameStateReader`。
返回 `false` 一律表示**动作未发生且状态零变化**（非法 key / 越界 / 无上下一关）。

### 2.2 后端/控制层 → UI（通知）

| 接口 | 实现方 | 方法 |
|---|---|---|
| `IRenderNotifier` | GameView | `void requestRender()` |
| `IStatusObserver` | HUD | `onGoldUpdated(int)` / `onLivesUpdated(int)` / `onWaveMessage(String)` |
| `ITowerSelectionNotifier` | `view/TowerDetailPanel` | `onTowerSelected(Tower)` / `onTowerDeselected()`（⚠️ 经 controller 的注线未做，现由 `GameView` 直连面板；`GameController.setSelectionNotifier` 暂空置） |

### 2.3 音效接口（素材/音效负责人实现，均为抽象方法）

| 接口 | 方法 | 触发点 |
|---|---|---|
| `IWaveSound` | `onWaveStarted(int waveNumber)` | GameController.startNextWave |
| `ITowerSound` | `onTowerPlaced(TowerType)` / `onTowerUpgraded(Tower)` / `onTowerSold(Tower)` | GameController 塔操作结算处 |
| `IUnitSound` | `onUnitSpawned(LivingEntity)` | 士兵/单位被生产时 |
| `ICombatSound` | `onProjectileFired(Projectile)` / `onProjectileHit(Projectile, LivingEntity)` / `onUnitAttack(LivingEntity, LivingEntity)` / `onUnitDied(LivingEntity)` / `onBossStomp()` | 投射物发射/命中、近战攻击、单位死亡、Boss 震地（实体经事件槽调用） |
| `IEndSound` | `onVictory()` / `onGameOver()` | GameController 胜负判定 |

> 实现与事件对照表见 `docs/音效扩展方法说明.md`。

### 2.4 视觉特效接口（GameView 实现）

| 接口 | 方法 |
|---|---|
| `IFloatingTextFx` | `showFloatingText(double x, double y, String text, String color)` |
| `IScreenFx` | `flashScreen(String color, int durationMs)` / `shakeScreen(int durationMs, int intensity)` / `showBossWarning()` |
| `IParticleFx` | `spawnExplosionParticles(double x, double y, String color, int count)` |
| `ISelectionFx` | `showSelectionHighlight(GameObject target)` / `clearSelectionHighlight()` |

### 2.5 model 层能力接口

`ICollidable`（`com.kingdom.game.model.ICollidable`）
- `double getCollisionRadius();`
- `boolean onCollision(GameObject other);`
- `boolean isCollisionEnabled();`

由 LivingEntity 统一实现；具体实体如需特殊碰撞反应，覆写 `handleEntityCollision` 钩子。

## 3. 抽象类说明

继承总览：

```
GameObject(抽象，位置/渲染/事件槽)
 ├── Tower(抽象, 无HP)            ← 塔
 ├── Projectile(抽象, 无HP)        ← 投射物
 └── LivingEntity(抽象, 有HP/阵营, implements ICollidable)
      ├── Enemy(抽象, 路径+拦截)   ← 敌人/Boss
      └── Ally(抽象, 友方索敌)     ← 士兵
```

### 3.1 `GameObject`（根，`model` 包）
- 构造：`GameObject(x, y)`（宽高取 `assets/sizes.json`）与 `GameObject(x, y, w, h)`。
- **事件槽字段**（protected，缺省 = `FxNop` 空实现）：`combatSound / fxText / fxScreen / fxParticle / fxSelection`。
- `attachEffects(ICombatSound, IFloatingTextFx, IScreenFx, IParticleFx, ISelectionFx)`：GameController 注册实体时统一注入；传 null 表示保持空实现。
- 抽象：`update()` / `render(GraphicsContext)`。
- `destroy()`：**只表示实体自我宣告，移出注册表由 GameController 唯一完成**。
- 贴图辅助：`sprite(AssetKey)`（取图，可能 null）与 `drawSprite(GraphicsContext, AssetKey)`（成功画图返回 true，失败供调用方回退色块）。

### 3.2 `LivingEntity`（活体，`model` 包）
- 构造：`(x, y, maxHp, speed, Faction)` 与 `(x, y, maxHp, speed, Faction, w, h)`。
- 字段：`maxHp/currentHp/speed`、`faction`（可 `setFaction` 运行期改阵营）、`attackDamage/attackCooldown/maxAttackCooldown`、`isStunned/stunTimer`、`damageTakenMultiplier`。
- `takeDamage(int)`：血量归零时统一触发 `combatSound.onUnitDied(this)` 再调用抽象 `onDeath()`；**返回实际扣血量**。
- `takeDamage(int damage, boolean ignoreReduction)`：两参重载；`ignoreReduction = true` 时无视承伤倍率（炮塔破甲路径）。
  承伤倍率由 `protected double damageTakenMultiplier`（默认 `1.0`）表达，`TankEnemy` 构造期按 `balance.json` 的 `tankPhysicalReduction` 设置。
- `tryAttack(LivingEntity)`：近战模板（眩晕/冷却/目标存活校验），成功后触发 `combatSound.onUnitAttack`。
- ICollidable：`getCollisionRadius()` = max(w,h)/2；`onCollision` 同阵营不反应，跨阵营调 `handleEntityCollision`（默认 false 可覆写）。
- `update()`：眩晕/冷却递减，存活且未眩晕时调抽象 `move()`。
- 抽象：`move()`、`onDeath()`。
- 关键 getter：`getCurrentHp/getMaxHp/getSpeed/isAlive()/getFaction/setFaction/getAttackDamage/getMaxAttackCooldown`。

### 3.3 `Enemy`（敌方，`model.enemy` 包）
- 构造：`Enemy(x, y, hp, speed, goldReward)` 与带战斗参数的 `(x, y, hp, speed, goldReward, attackDamage, attackCooldownMs)`，内部 Faction.ENEMY。
- **数值来源**：HP / 速度 / 赏金经 `GameConfig`（源头 `config/balance.json`）；**近战攻击力 / 冷却经 `config/balance.json` 的 8 个 `*AttackDamage` / `*AttackCooldownMs` 键**（`GameController.spawnEnemy` 显式传参，实体类兜底走 `BalanceTable.runtime()`），实体类内不再写死战斗数值。
- 路径：`followPath()`（逐点走，走完调 `onReachEnd()`）；`setPath(pathX, pathY)`。
- 拦截追击：`handleEntityCollision(Ally)` 置 `isEngaged/engagedTarget` 并近战；`move()` 模板 = 有目标追击、无目标回路径。
- `onReachEnd()`：置 `reachedEnd=true` + 飘字 `-1 ❤`；扣生命由 GameController 完成。
- 死亡抽象 `onDeath()` 交由子类（金币结算在 GameController）。

### 3.4 `Ally`（友方，`model.ally` 包）
- 构造：`(x, y, hp, speed, attackDamage, attackCooldown)`，内部 Faction.ALLY。
- 抽象：`findTarget(List<Enemy> enemies)`（索敌策略）。
- `handleEntityCollision(Enemy)`：近战反击；`target` 字段记录当前目标。
- `move()` 仍为抽象，由士兵具体类实现「追击最近敌人」。

### 3.5 `Tower`（塔，`model.tower` 包）
- 字段：`attackRange/attackCooldown/currentCooldown/baseAttackDamage/totalCost/isStunned`（`level`/`upgradeCostBase` 已随死代码删除；等级改由类身份表达，见 §3.5.1）。
- 世界能力通道：`setProjectileSink(Consumer<Projectile>)`（GameController 放置时注入）+ protected `fire(Projectile)`。
- 抽象：`findTarget(List<Enemy>)` / `attack(Enemy)`。
- `tryAttack(List<Enemy>)`：冷却后索敌开火（GameController 每帧调用）；`sell()` 返 50% 投入。`upgrade()` 与 `getUpgradeCost()` **已删除**（原为无调用方的死代码），升级改走 `ITowerUpgrade` 换类原位替换。
- `stun(int)` 供 Boss 震地眩晕。

### 3.5.1 塔升级契约（三级升级链；每级 = 不同塔类）
> 详细设计见 `docs/防御塔子系统说明.md`「第二部分：塔升级体系」。
- 每个等级 = **独立 `TowerType` 常量 + 独立塔类**，形成三级链：
  - 箭塔 `ARROW/ArrowTower` → `ARROW_ELITE/EliteArrowTower` → `ARROW_MASTER/MasterArrowTower`
  - 炮塔 `CANNON/CannonTower` → `CANNON_ELITE/EliteCannonTower` → `CANNON_MASTER/MasterCannonTower`
  - 兵营 `BARRACK/Barrack` → `BARRACK_ELITE/EliteBarrack` → `BARRACK_MASTER/MasterBarrack`
  （各级**升级费**见塔类 `UPGRADE_COST` 常量，运行时统一经 `nextLevelSpec.getCost()` 取用，本文档不抄写数字。）
- 可升级塔实现 **model 能力接口 `model.tower.ITowerUpgrade`**：
  ```java
  public interface ITowerUpgrade {
      /** 本塔「更高一级塔」的目录条目（type/显示名/造价）；null = 已是最高级 */
      TowerSpec getNextLevelSpec();
      /** 是否已满级 */
      boolean isMaxLevel();
      /** 本塔等级（由类身份决定：1/2/3） */
      int getLevel();
  }
  ```
- **3 级特殊能力接口**：`IChainShot`（箭塔 3 级·连锁箭）、`IBurnEffect`（炮塔 3 级·燃烧）、`IHealAura`（兵营 3 级·治疗光环），参数均由 `config/tower.json` 对应键提供。
- **升级动作 = 原位「删旧塔、放新塔」**：GameController 校验 `next != null` → 扣升级费 → 用下一级工厂在原坐标建新塔（复用 `setProjectileSink` / `attachFx` 接线）→ 移除旧塔、加入新塔 → 通知；兵营升级/出售前会先释放其产出的士兵。
- **目录拆分**：可建造目录只列 1 级塔（升级级规格不进 `towerSpecs` / 建塔菜单），`towerFactories` 登记同一升级族全部等级且不污染菜单。
- **UI 只经 `ITowerUpgrade` 预览升级结果**：`getNextLevelSpec()` 给出下一级名称/造价、`isMaxLevel()` 满级隐藏升级按钮；不 import 具体塔类做分支。
- **等级**：由类身份表达——各塔类 `public static final int LEVEL`（1/2/3）+ `ITowerUpgrade.getLevel()`；详情面板经该接口显示「等级 Lv.N」。`Main` 已登记三族全部等级工厂，L2→L3 运行期可用。

### 3.6 `Projectile`（投射物，`model.projectile` 包）
- 双构造：
  - 追踪：`(x, y, Enemy target, int damage, double speed)` —— 飞行中实时锁定目标位置；
  - 定点：`(x, y, double tx, double ty, int damage, double speed)`。
- `Bomb` 另有带 `splashRadius` 的重载（半径由 `balance.json` 提供）。
- `update()`：未命中则 `fly()`；命中（`hasHit() == true`）后由 GameController 调用一次抽象 `onHit(List<Enemy>)` 并移除。
- 抽象：`onHit(List<Enemy> enemies)`（单体扣血 / AOE 溅射）。`Arrow` 走承伤倍率，`Bomb` 走破甲（`takeDamage(damage, true)`）。

### 3.7 具体类示例：`NormalEnemy`（`model.enemy`）
- 继承 Enemy 的移动/拦截模板，不写死战斗数值；
- `onDeath()`：空实现（结算归 GameController）；
- `render()`：贴图优先（`AssetKey.NORMAL_ENEMY`），缺失回退色块 + 头顶血条。

## 4. 枚举、数据类与扩展方式

### 4.1 `Faction`（`model`）—— 敌我阵营
值：`ALLY` / `ENEMY`。新增阵营：在此追加常量即可，使用方统一经 `getFaction()`；运行期阵营可变（`setFaction`）。

### 4.2 `TowerType`（`model`）—— 塔类型 id
当前值（9 个，三族三级升级链）：`ARROW / ARROW_ELITE / ARROW_MASTER / CANNON / CANNON_ELITE / CANNON_MASTER / BARRACK / BARRACK_ELITE / BARRACK_MASTER`。

**新增塔流程**（防御塔负责人执行）：
1. 新建具体 `Tower` 子类；
2. 需要新 id 时在本枚举追加一个常量；
3. 在装配处（Main）登记：
   ```java
   controller.registerTower(TowerType.CANNON,
       new TowerSpec(TowerType.CANNON, "炮塔", 80),
       (x, y) -> new CannonTower(x, y));
   ```
   造价/显示名**不写在枚举**，统一经 `TowerSpec`；升级级用 `registerUpgradeFactory` 登记（不进建塔菜单）。

**等级/升级族**：同一升级族每个等级 = 一个独立 `TowerType` 常量 + 独立塔类；1 级才进入「可建造目录」，更高级别只经升级路径出现（原位替换），可升级塔实现 `model.tower.ITowerUpgrade`（见 §3.5.1）。

### 4.3 `AssetKey`（`model`）—— 贴图词汇表
每个值对应 `src/main/resources/assets/<文件名>.png`（含三族 L1/L2/L3 全部塔图）。素材收集者只需按此命名放图，渲染层自动生效；未放图则回退色块。

### 4.4 `TowerSpec`（`model`）—— 塔目录条目
`TowerSpec(TowerType type, String displayName, int cost)`。建塔菜单经 `IGameStateReader.getTowerSpecs()` 读取。

### 4.5 地图/塔位数据契约（按地图分包）
- **地图组织**：`src/main/resources/maps/index.json` 注册表（`{maps:[{key,name,image}]}`）+ 每张地图目录 `maps/<key>/`，内含底图、`path.json`（MapRoute）、`spots.json`（TowerSpots）、`waves.json`（LevelWaves）；`util/map/MapLibrary` 负责列表/新建/读写/删除。
- **可建塔点位唯一来源**：`util/map/TowerSpots` + 当前地图的 `maps/<key>/spots.json`（由 `TowerSpotEditorTool` 标注导出；`GameConfig` 经 `MapLibrary.readSpotsFromClasspath(key)` 加载）。
- **敌人路径**：当前地图 `maps/<key>/path.json`（`PathEditorTool` 标注），`GameConfig` 经 `MapLibrary.readPathFromClasspath(key)` 加载；活动地图 = index 第一条（可用 `-Dmap.key=<key>` 指定）。
- **明令废弃** `buildSlots` / `setBuildSlots` 之类「第二套塔位数据通道」，禁止再新增并行点位数据。
- UI 建塔交互（点击命中塔位、弹目录、落塔坐标）统一读取 `config.getTowerSpots()`；
- 落塔仍走 `ITowerBuilder.placeTower(x, y, type)` 后端校验（金币/越界/距路径/塔间距），失败经 `IStatusObserver` 提示；
- 塔位坐标语义与游戏一致：像素坐标、点位即「塔位中心」。

### 4.6 单位行为动画（JSON 动画库；适用敌人/友方/防御塔）
> 适用范围：敌人、友方（士兵等）、防御塔三类可渲染单位；按「类别(kind) + 单位名」组织。
- 每个单位一个动画表文件：`src/main/resources/assets/animations/{enemies,allies,towers}/<单位名>.json`
  ```json
  { "kind": "enemies", "name": "normal_enemy", "interval": 6,
    "modes": { "idle": ["enemies/normal_enemy/idle_0.png", "..."],
               "walk": ["..."], "attack": ["..."], "death": ["..."] } }
  ```
  - `kind`：`enemies | allies | towers`（决定存放目录与默认模式组）；
  - `interval`：每张关键帧停留的 tick 数（约 60 tick/s）；`modes` 键即「行为模式」，**可随意增删**；
  - 帧路径相对 `assets/`，帧图放 `assets/<kind>/<单位名>/<模式>_<序号>.png`；
  - 默认模板模式：敌人/友方 → `idle/walk/attack`；防御塔 → `idle`（常时循环；暂不分「开火帧」）。
- 工具类：
  - `util/anim/AnimTable`：模型含 `kind/name/interval/modes` + `toJson/fromJson/loadFromClasspath`、`template(kind,name)`；
  - `util/anim/AnimLibrary`：按 类别+单位名 管理（同类别同名 = 覆盖去重）——`list(kind)` / `read(kind,name)` / `exists(kind,name)` / `save` / `delete(kind,name)` / `framesDir(kind,name)`；
  - `util/editor/AnimEditorTool` / `AnimEditorLauncher`：可视化编辑器。
- **渲染接入点**：游戏内由渲染叠加层读取对应单位 JSON；`util.anim.UnitAnimator` + GameView 敌/友/塔循环 + `Main` 登记 **8 类**单位，无帧图/未注册时保持原渲染。渲染契约见 §4.7。
  - 已登记：4 类敌人、`Soldier`/`EliteSoldier`/`RoyalSoldier`、`ArrowTower`；三者各有独立动画表（`elite_soldier.json` / `royal_soldier.json` 各自成表，不共用 `soldier.json`）。
  - 未登记：炮塔 / 兵营 / 其余 6 个精英·大师塔（保持静态渲染）；`towers/arrow_tower.json` 目前仅有模板、`idle` 帧列表为空。

### 4.7 单位/活体动态渲染契约（外部叠加层，已实现）
> 详细设计见 `docs/单位行为动画-渲染层设计.md`。本小节为契约要点。
> 适用：**Enemy / Ally / Tower 及其子类均不改**，动画由「外部观察 + 叠加绘制」实现（单位类不实现任何动画接口）。

- **模式判定外置（单位无模式字段）**——渲染层用公开状态逐帧推导，规则按「单位类型」注册：
  | 类别 | 模式规则 |
  |---|---|
  | 敌人/友方（LivingEntity） | 眩晕 `isStunned()`→`idle`；近战贴身攻击中→`attack`；本帧位移>0→`walk`；否则 `idle`（模式表可另配 `death` 等） |
  | 防御塔 | **常时 `idle` 循环**；如需开火帧，未来需给 Tower 增加只读指示（本轮不动基类） |
- **组件契约**：
  - `util/anim/UnitPoseResolver`：纯规则解析（单位状态 + 位移 → 模式名），规则按单位类型可增删；
  - `util/anim/UnitAnimator`：按单位实例记录上帧坐标/tick；`overlay(GraphicsContext, GameObject)` 在该单位 `render()` 之后叠加「当前模式当前帧」贴图（参数按 GameObject，兼容塔等非 LivingEntity）；
  - 注册：`registerUnitAnimation(kind, 单位类名, "/assets/animations/<kind>/<单位名>.json")`；
  - 帧推进：每游戏 tick 按 `AnimTable.interval` 前进（约 60 tick/s）。
- **查表与回退**：模式名 → 该单位 AnimTable `modes[模式]`；缺键/缺帧图/未注册 → **无操作，单位保持自身原渲染**，保证回归无损。
- **叠加范围**：以 `(getX(), getY(), getWidth(), getHeight())` 中心绘制在该单位身体区；活体自绘血条位于身体上方不受影响。
- **接入点**：`GameView` 敌人/友方/塔绘制循环各加一行 `render(gc); animator.overlay(gc, unit);`（单位代码不改）。
- **扩展**：新增行为 = 给该单位 JSON 加 `modes` 键并配帧 + 给该单位类型注册判定规则；模式命名建议小写下划线。

## 5. 数值与素材来源

### 5.1 `GameConfig`（`config`）
- 实例对象 + getter / fluent setter；数值来自 `config/balance.json`（`util.balance.BalanceLibrary` 读取，缺省回退内置默认），**运行期唯一 getter 入口不变**；开发期调参请改该 JSON（重启生效），`Main` 里的 `setXxx(...)` 仅作运行期瞬时覆盖。
- 集中字段：画布、初值（金币/生命/波次）、四类敌人 HP/速度/赏金与近战参数、路径、配色（完整归属见《数值配置 JSON 化规范》§0）。
- 塔目录容器：`addTowerSpec(TowerSpec)` / `getTowerSpecs()` / `getTowerSpec(TowerType)`。
- **塔数值**（伤害/射程/冷却/士兵属性）来自 `config/tower.json`（`util.balance.TowerBalance` 构造期读取，缺省回退调用点默认值）；溅射半径走 `config/balance.json`；造价与升级链仍留塔类常量。

### 5.2 `util/asset/Assets`（贴图仓库）
- 文件放 `src/main/resources/assets/`，Maven 路由到 classpath；
- `Image get(AssetKey)` 懒加载并缓存，缺失返回 null；`preload()` 启动预载。
- 实体宽高由 `util/asset/SizeTable` 读 `assets/sizes.json`（见《视觉尺寸配置规范》）。

### 5.3 `util/fx/FxNop`（空实现单例）
因接口无 default 方法，`FxNop` 提供 9 个空实现实例（`NO_WAVE_SOUND` … `NO_SELECTION_FX`），作为实体事件槽缺省值与「未接线不 NPE」的兜底。

### 5.4 `GameState` / `WaveManager`
- `GameState`：金币/生命/波次纯数据 + `applyConfig(GameConfig)` + `reset()`；
- `WaveManager`：按时间出怪节奏（`beginWave(List<SpawnOrder>)`）+ `reset()`。

## 6. 控制器与接线

`GameController`（实现 `ITowerBuilder / IWaveStarter / IGameLoop / IGameStateReader / ILevelSwitcher`）：
- 持有四类实体注册表 `enemies/towers/projectiles/allies` 与塔工厂注册表；
- `update()` 每帧顺序：出怪 → 塔索敌开火 → 投射物飞行/命中（onHit 后移除）→ 友方 AI → 敌我碰撞 → 敌人移动/结算（终点扣命、死亡赏金）→ 波次结束/胜负 → `requestRender()`；
- 塔放置：金币校验 + 越界/路径/重叠校验 + 工厂创建 + `setProjectileSink` + `attachEffects`；
- 实体注册时统一注入事件通道；兵营经 `setAllySink(this::addAlly)` 产出士兵；
- 关键常量：`PATH_CLEARANCE`（离路径最小距离）、`TOWER_SPACING`（塔间距）、`BOSS_STOMP_STUN_MS`（震地眩晕时长）；
- `resetGame()` 支持重新开局；关卡切换/重开（`ILevelSwitcher`）见《多关卡与运行期切图-接口规范》§3。

Main 接线示例（唯一注入点）：
```java
controller.setStatusObserver(hud);
controller.setRenderNotifier(view);
controller.setFloatingTextFx(view);   // GameView 实现视觉特效
controller.setScreenFx(view);
controller.setParticleFx(view);
controller.setSelectionFx(view);
controller.setWaveSound(SoundManager.getInstance());   // 音效 5 个接口同一实例
```

## 7. 常见扩展流程

| 场景 | 谁做 | 步骤 |
|---|---|---|
| 新增一种塔 | C | 写子类 → `TowerType` 加值（如需）→ Main 里 `registerTower` + `registerUpgradeFactory`（`attack()` 生成投射物后 `fire()`） |
| 新增一种敌人 | B | 继承 `Enemy` → 定数值构造/`onDeath`/`render`（战斗数值走 `balance.json` 键） |
| 新增一种投射物 | B | 继承 `Projectile`（选追踪/定点构造）→ **必须实现可运行的 `onHit()` / `render()`** |
| 新增士兵 | B | 继承 `Ally` → `move()`/`findTarget()`/`onDeath()`/`render()` |
| 调数值 | F | 改 `config/balance.json`（塔/士兵改 `config/tower.json`）→ 重启生效 |
| 提供贴图 | E | 按 `AssetKey` 文件名放 `resources/assets` → 重启生效 |
| 提供音效 | E | 实现 `util/audio/SoundManager` 并在 Main 注入 |
| 做建塔菜单/详情面板 | D | 读 `IGameStateReader` + 调 `ITowerBuilder` / `ITowerUpgrade` |
| 做特效 | D | 在 GameView 里填充 `IFloatingTextFx` / `IScreenFx` / `IParticleFx` / `ISelectionFx` |
