> 编制：李贤宇（E：素材与音效负责人）｜日期：2026-09-09
> 适用版本：dev（含 `util/audio/SoundManager` 后）
> **2026-09-11 修订**（D 执行、A 授权）：漏怪音已在 `view/HUD` 接线（§二）；**金币不足音效取消**（§2.1）；

## 一、怎么拿到 SoundManager

`SoundManager` 是单例，**任何类直接调用即可，不需要注入或传递**：

```java
import com.kingdom.game.util.audio.SoundManager;

SoundManager.getInstance().onLifeLost();      // 例：漏怪时
```

（Main 已把它注入 controller 的 5 个标准接口，走接口的音效——波次/塔三连/战斗/胜负——交互侧**不用管**，事件到了自动响。）

## 二、扩展方法清单（供交互侧调用）

| 方法 | 触发时机 | 实际调用点 | 音效 |
| :--- | :--- | :--- | :--- |
| `void onLifeLost()` | 敌人到达终点、生命 -1 | `view/HUD.onLivesUpdated(int)`（HUD 实现 `IStatusObserver`）：**自持上一次生命值**，`新生命 < 旧生命` 时调用 | `life_lost.wav`（失败警报音） |

调用示例（即 `HUD` 内的实际写法，2026-09-11 已接线）：

```java
@Override
public void onLivesUpdated(int lives) {
    if (lastLives >= 0 && lives < lastLives) {   // 只在"下降"时触发
        SoundManager.getInstance().onLifeLost();
    }
    lastLives = lives;
    livesLabel.setText("生命 " + lives);
}
```

> **两处原表述已订正（2026-09-11）**：
> 1. `IStatusObserver` 只有 `onLivesUpdated(int)` 单参版本（**不存在** `onLivesChanged(int oldLives, int newLives)`），旧值需调用方自持；`lastLives` 初值取 `-1` 以屏蔽"首次推送"。原文伪代码里的 `onPlaceTowerFailed(String reason)` 同样不存在于契约。
> 2. 原写「两个方法内部自带防抖，重复触发不会叠音」**与代码不符**：`onLifeLost()` 走的是 `SoundManager.play(...)`（其注释自称"无节流播放"），**没有 gapMs 守卫**。因此**同一帧多只敌人进家会连响多次**；若要防抖，请 E 改用现成的 `playThrottled(...)`，调用方无需改动。

### 2.1 已取消：金币不足音效（2026-09-11 裁定，与 A 讨论后定案）

`onGoldInsufficient()` / `gold_insufficient.wav` **不采用**，理由三条：

1. 建造菜单与升级按钮已按金币**逐帧置灰**（`TowerBuildMenu` / `TowerDetailPanel`，由 `GameView` 每帧 `refresh()` 驱动）→ 玩家点不到买不起的塔，该分支在 UI 路径上**不可达**；
2. `ITowerBuilder.upgradeTower` 返回 **`void`**（UI 连失败都感知不到），`placeTower` 的 `false` **不区分**失败原因（未开放 / 越界 / 压路 / 重合 / 金币不足共 5 种）；
3. 唯一线索是 `notifyMessage("金币不足！…")` 这条**带可变后缀**的文案，且与波次/胜负消息共用同一个 last-writer-wins 标签 → 字符串匹配不可靠。

> **待 E 清理**：删 `SoundManager.onGoldInsufficient()` 与资产 `assets/sounds/gold_insufficient.wav`。

## 三、内置节流阀说明（防吵机制）

战斗类音效自带**最小播放间隔**，间隔内重复触发直接丢弃：

| 音效 | 最小间隔 |
| :--- | :--- |
| 单位死亡（随机 4 选 1 + 随机变调） | 150ms |
| 近战攻击 | 150ms |
| 箭矢发射 / 命中 | 60ms |
| 炸弹爆炸 | 100ms |
| 单位出场 | 300ms |

也就是说：怪物扎堆死亡时，死亡音**最多每 150ms 响一次**（约每秒 6 次上限，且每次音调略有差异），不会出现一波怪同时死导致的爆音刷屏。波次/塔操作/胜负属于一次性事件，不节流。

如果联调时觉得某个音效还是太密/太稀，直接找 E 改 `SoundManager` 里对应的间隔数字即可，调用方不用动。
