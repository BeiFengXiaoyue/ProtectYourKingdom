# 音效扩展方法说明（交互侧对接用）

> 归属：素材与音效（E）；交互侧接线（D）
> 适用版本：`dev`（含 `util/audio/SoundManager` 后）
> **数值口径**：节流间隔与音量是 `SoundManager` 内的常量，本文档只列语义与量级。

---

## 一、怎么拿到 SoundManager

`SoundManager` 是单例，**任何类直接调用即可，不需要注入或传递**：

```java
import com.kingdom.game.util.audio.SoundManager;

SoundManager.getInstance().onLifeLost();      // 例：漏怪时
```

`Main` 已把它注入 controller 的 5 个标准接口，走接口的音效——波次 / 塔三连 / 战斗 / 胜负——交互侧**不用管**，事件到了自动响。

---

## 二、扩展方法清单（供交互侧调用）

| 方法 | 触发时机 | 实际调用点 | 音效 |
| :--- | :--- | :--- | :--- |
| `void onLifeLost()` | 敌人到达终点、生命 -1 | `view/HUD.onLivesUpdated(int)`（HUD 实现 `IStatusObserver`）：**自持上一次生命值**，`新生命 < 旧生命` 时调用 | `life_lost.wav` |

调用示例（即 `HUD` 内的实际写法）：

```java
@Override
public void onLivesUpdated(int lives) {
    if (lastLives >= 0 && lives < lastLives) {   // 只在「下降」时触发
        SoundManager.getInstance().onLifeLost();
    }
    lastLives = lives;
    livesLabel.setText("生命 " + lives);
}
```

> **两点必须知道**：
> 1. `IStatusObserver` 只有 `onLivesUpdated(int)` **单参**版本（不存在 `onLivesChanged(old, new)`），旧值需调用方自持；`lastLives` 初值取 `-1` 以屏蔽「首次推送」。
> 2. `onLifeLost()` 走的是**无节流**的 `play(...)`，**没有 gapMs 守卫** → 同一帧多只敌人进家会连响多次。若要防抖，改用现成的 `playThrottled(...)`，调用方无需改动。

### 2.1 金币不足音效：已取消（代码与资产均已移除）

`onGoldInsufficient()` / `gold_insufficient.wav` **不采用**，理由三条：

1. 建造菜单与升级按钮已按金币**逐帧置灰**（`TowerBuildMenu` / `TowerDetailPanel`，由 `GameView` 每帧 `refresh()` 驱动）→ 玩家点不到买不起的塔，该分支在 UI 路径上**不可达**；
2. `ITowerBuilder.upgradeTower` 返回 **`void`**（UI 连失败都感知不到），`placeTower` 的 `false` **不区分**失败原因（未开放 / 越界 / 压路 / 重合 / 金币不足）；
3. 唯一线索是 `notifyMessage("金币不足！…")` 这条**带可变后缀**的文案，且与波次/胜负消息共用同一个 last-writer-wins 标签 → 字符串匹配不可靠。

> 方法、类头 Javadoc 链接与 `assets/sounds/gold_insufficient.wav` 均已删除，**不要再接线**。

## 三、内置节流阀说明（防吵机制）

战斗类音效自带**最小播放间隔**，间隔内重复触发直接丢弃：

| 音效 | 最小间隔 |
| :--- | :--- |
| 单位死亡（随机 4 选 1 + 随机变调） | 150ms |
| 近战攻击 | 150ms |
| 炸弹爆炸 | 100ms |
| 箭矢发射 / 命中 | 60ms |
| 单位出场 | **无节流**（仅把音量压低到 `DEFAULT_VOLUME` 的一半量级） |

也就是说：怪物扎堆死亡时，死亡音**最多每 150ms 响一次**，不会出现一波怪同时死导致的爆音刷屏。波次 / 塔操作 / 胜负属于一次性事件，不节流。

若联调时觉得某个音效太密/太稀，直接改 `SoundManager` 里对应的间隔常量即可，调用方不用动。
