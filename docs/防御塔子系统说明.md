## 第一部分：塔参数与契约

### 1. 三种防御塔一览

| 塔 | 类型枚举 | 造价 | 伤害 | 射程 | 攻击/生产间隔 | 机制 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 箭塔 ArrowTower | `ARROW` | 50 | 18 | 120 | 550ms | 单体，追踪 `Arrow` |
| 炮塔 CannonTower | `CANNON` | 80 | 25 | 120 | 900ms | 群攻，定点 `Bomb`，落点溅射 |
| 兵营 Barrack | `BARRACK` | 100 | — | — | 3s/个（上限 3，每槽位独立；死后 3s 补位） | 生产 `Soldier` 拦截敌人 |

> **数值来源**：造价（50/80/100）与兵营"3 秒 1 个、上限 3"为 **PRD 明确给定值**；伤害 / 射程 / 冷却 / 士兵属性均为**占位可调值**。PRD §16.2 声明全部数值以《游戏规则说明书》与 GameConfig 为准，后续统一核对微调。
>
> **兵营生产语义**：兵营维护 `maxSoldiers` 个槽位，**每个槽位各带独立补位计时器**。士兵阵亡后该槽位独立重新计时 `spawnIntervalMillis` 再补位（不再是"死亡立即复活"），未阵亡的其它槽位不受影响；初始错峰产出（0 / 间隔 / 2×间隔 …）；眩晕时暂停生产。

### 2. 共同契约（继承 `Tower` 基类）

- 子类须实现 `findTarget(List<Enemy>)`、`attack(Enemy)`、`render(GraphicsContext)`。
- 数值字段（`attackRange / attackCooldown / baseAttackDamage / upgradeCostBase / totalCost`）在构造函数内自填；**`totalCost` 必须播种造价**，否则 `sell()` 返还恒为 0。
- 发射统一走 `fire(Projectile)` → `projectileSink`（GameController 在 `placeTower` 接入）。
- `upgrade()` 伤害 ×1.3、`sell()` 返还 `totalCost / 2` 由基类提供，子类可直接沿用。

### 3. 兵营——友方出口（接口已就绪，待 A 接线）

`Barrack` **未修改 `Tower` 基类**，自带一条友方出口（仿 `projectileSink` 写法）：

```java
private Consumer<Ally> allySink = a -> { };          // 默认 no-op
public void setAllySink(Consumer<Ally> sink) { ... }
protected void produce(Ally soldier) { allySink.accept(soldier); }
```

- **接口已就绪，默认 no-op**：在 A 于 `GameController.placeTower` 接入
  `barrack.setAllySink(ally -> { allies.add(ally); attachFx(ally); if (unitSound != null) unitSound.onUnitSpawned(ally); })`
  之前，兵营产出的士兵**不会进战场**（被 no-op 出口吞掉）。
- 兵营内部自持有役士兵列表，按 `isAlive()` 剪除死亡单位，据此判定上限 3。

### 4. 跨层依赖状态

| 类 | 归属 | 状态 |
| :--- | :--- | :--- |
| `Bomb.onHit` | 实体(B) | ⏳ 待 B 填充：落点半径 ~60px 内所有存活敌人 `takeDamage` → 炮塔 AOE 溅射 |
| `Soldier.move/findTarget` | 实体(B) | ✅ 已实现（追击最近敌人 + 近战 + 回防） |
| 士兵索敌"轮询" | 控制层 | ✅ 已接线：`GameController` 友方循环每帧 `a.pollTarget(enemies)` → 写入 `Ally.target`，使士兵主动扑向视野内敌人（此前无人轮询，士兵只会被动等敌人撞上来） |

> CannonTower / Barrack 只负责"产弹 / 产兵"；炮塔 AOE 半径（~60px）由 B 在 `Bomb.onHit` 内实现，士兵拦截已通。

### 5. 新增一种塔的扩展流程

1. 在 `TowerType` 追加一个枚举常量（本文件由塔负责人维护）；
2. 新建对应 `Tower` 子类，实现 `findTarget / attack / render` 并自填数值字段；
3. 在 `Main` 里 `registerTower(type, new TowerSpec(type, "显示名", 造价), XxxTower::new)` 上架。

## 第二部分：塔升级体系

### 6. 目标与约束

- **每个等级是不同的塔**：如 `ARROW / ArrowTower`（1 级）→ `ARROW_ELITE / EliteArrowTower`（2 级，更强的箭塔）；
- **可升级对象实现一个接口**，接口能给出"更高一级塔是哪个"；
- **交互层（UI）只依赖该接口**得知升级结果（下一级名称 / 造价 / 是否满级），不 import 具体塔类、不做 instanceof 分派；
- **升级动作 = 原位"删旧塔、放新塔"**：在旧塔坐标移除旧塔，放置同一族的下一级新塔；
- 基于现有 `GameController`（单编排中枢 + 注册表 + placeTower 建塔流程）扩展，不推翻其结构。

### 7. 现状摘要（对接基线）

- `GameController`：唯一编排类，实现 `ITowerBuilder / IWaveStarter / IGameLoop / IGameStateReader`；
  持有 `GameState`、`WaveManager`、`GameConfig`、`enemies/towers/projectiles/allies` 注册表、
  `Map<TowerType, BiFunction<Double,Double,Tower>> towerFactories` 与若干通知接口；
  每帧统一驱动 + 结算，金币/生命/列表移除唯一在此；UI 全部经接口访问。
- `placeTower(x,y,type)`：越界/离路径≥30/塔间距≥40/金币校验 → `factory.apply(x,y)` →
  设坐标 → `setProjectileSink(p -> projectiles.add(p))` → `attachFx` → 加入 `towers` → 扣 `spec.cost` → 通知/重绘。
- `upgradeTower(tower)` **现状为数值式**（扣 `tower.getUpgradeCost()` 后 `tower.upgrade()`，level++、伤害×1.3）——与"换类升级"冲突，本设计将改写。
- `TowerType` 现含 `ARROW / ARROW_ELITE / CANNON / BARRACK`；`Tower` 本身无类型身份/下一级查询（升级链信息在其子类/注入处）。
- `ITowerUpgrade` 纯预留 → **现已由 C 提供接口并实现**（见 §9）；`ITowerSelectionNotifier` 仍未接线、无实现类。
- 建塔菜单会把 `config.towerSpecs` 全量列出 → 升级级塔不能直接进该目录（见 §10）。

### 8. 等级模型（每级 = 独立类型 / 类）

| 等级 | 类型枚举 | 塔类 | 说明 |
| :--- | :--- | :--- | :--- |
| 箭塔 1 级 | `ARROW` | `ArrowTower` | 可升级（实现 `ITowerUpgrade`） |
| 箭塔 2 级（满级） | `ARROW_ELITE` | `EliteArrowTower`（继承 ArrowTower） | 满级，`getNextLevelSpec()` 返回 null |
| 炮塔 1 级 | `CANNON` | `CannonTower` | 可升级（实现 `ITowerUpgrade`） |
| 炮塔 2 级（满级） | `CANNON_ELITE` | `EliteCannonTower`（继承 CannonTower） | 满级，`getNextLevelSpec()` 返回 null |
| 兵营 1 级 | `BARRACK` | `Barrack` | 可升级（实现 `ITowerUpgrade`） |
| 兵营 2 级（满级） | `BARRACK_ELITE` | `EliteBarrack`（继承 Barrack） | 满级，`getNextLevelSpec()` 返回 null |

### 9. `ITowerUpgrade` 接口契约（C 已提供并实现）

```java
// model/tower/ITowerUpgrade.java
public interface ITowerUpgrade {
    TowerSpec getNextLevelSpec();   // 更高一级塔目录条目；null = 已满级
    boolean isMaxLevel();
}
```

- UI 详情面板只依赖此接口，不 import 具体塔类、不做 instanceof 分派；
- 三个 1 级塔均实现 `ITowerUpgrade`，默认 `nextLevelSpec` 指向各自 2 级条目，并提供 `setNextLevelSpec(TowerSpec)` 供 A 注入/替换链（推荐注入，升级链数据收敛在登记处）：
  - `ArrowTower` → `ARROW_ELITE`（"精英箭塔"，升级价 90）
  - `CannonTower` → `CANNON_ELITE`（"精英炮塔"，升级价 100）
  - `Barrack` → `BARRACK_ELITE`（"精英兵营"，升级价 120）

### 10. 目录拆分约定（重要）

- **可建造目录**（建塔菜单数据源，`IGameStateReader.getTowerSpecs()`）**只列 1 级塔**；
- 各级升级规格**不进 `config.towerSpecs` / 建塔菜单**；
- `GameController.towerFactories` 登记该族所有等级的工厂（供"原位替换"取下一级工厂用）；
- `GameConfig.addTowerSpec(...)` 只登记 1 级塔 → 避免高级塔出现在菜单。
- **注意**：现状 `registerTower(type, spec, factory)` 会内部 `addTowerSpec(spec)`，会污染菜单——为精英塔需增一条**不写目录**的纯工厂注册路径。

### 11. 原位替换流程（升级动作，交由 A 落实）

```
ITowerBuilder.upgradeTower(tower):
  1. 校验：tower 实现 ITowerUpgrade 且 getNextLevelSpec()!=null，否则提示"已满级"并返回；
  2. 扣升级费（费用语义见 §12，由实现者定义）；
  3. 取下一级 spec 与 factory → 在 tower 的 (x,y) 建新塔；
  4. 复用 placeTower 的接线：setProjectileSink(p -> projectiles.add(p)) + attachFx(新塔)；
  5. 旧塔 destroy() 并从 towers 移除；
  6. 新塔加入 towers；
  7. 通知 IStatusObserver（金币/消息）、ITowerSound.onTowerUpgraded(新塔)、requestRender()。
```
建议：把 `placeTower` 内部抽成 `private Tower buildTowerAt(double x,double y,TowerType type, boolean deduct)`，建塔与升级共用，保证接线一致。

### 13. UI 接入建议（详情面板/选中，后续 D 实现）

- `ITowerSelectionNotifier` 真正接线：Main 注入 → GameController 在"点中塔/取消"时回调；
- 详情面板拿到选中 `Tower` 后，**只经 `ITowerUpgrade`**：
  - `getNextLevelSpec()` 非 null → 显示"升级为 <显示名> (<造价>)"按钮；
  - `isMaxLevel()` → 隐藏/置灰升级按钮；
  - 点击调用 `ITowerBuilder.upgradeTower(tower)`；
- 全程不 import 具体塔类。
