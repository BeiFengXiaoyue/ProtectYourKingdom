## 第一部分：塔参数与契约

### 1. 三种防御塔一览

| 塔 | 类型枚举 | 造价 | 伤害 | 射程 | 攻击/生产间隔 | 机制 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 箭塔 ArrowTower | `ARROW` | 50 | 18 | 120 | 550ms | 单体，追踪 `Arrow` |
| 炮塔 CannonTower | `CANNON` | 80 | 45 | 140 | 1500ms | 群攻，定点 `Bomb`，溅射 50 |
| 兵营 Barrack | `BARRACK` | 100 | — | — | 5s/个（上限 2，升级后 3/4，每槽位独立；死后 5s 补位） | 生产士兵拦截敌人（1/2/3 级产 `Soldier`/`EliteSoldier`/`RoyalSoldier`） |

> **数值来源**：造价（50/80/100）沿用 **PRD**；伤害/射程/间隔/溅射/士兵属性按 **《建筑与怪物机制策划 v1.1》**；兵营出场·重生间隔取 **5s**（经确认覆盖文档的 10s）。三级升级见 §8/§14。
>
> **兵营生产语义**：兵营维护 `maxSoldiers` 个槽位，**每个槽位各带独立补位计时器**。士兵阵亡后该槽位独立重新计时 `spawnIntervalMillis`（5s）再补位（不再是"死亡立即复活"），未阵亡的其它槽位不受影响；初始错峰产出（0 / 间隔 / 2×间隔 …）；眩晕时暂停生产。

### 2. 共同契约（继承 `Tower` 基类）

- 子类须实现 `findTarget(List<Enemy>)`、`attack(Enemy)`、`render(GraphicsContext)`。
- 数值字段（`attackRange / attackCooldown / baseAttackDamage / totalCost`）在构造函数内自填；**`totalCost` 必须播种造价**，否则 `sell()` 返还恒为 0。
- 发射统一走 `fire(Projectile)` → `projectileSink`（GameController 在 `placeTower` 接入）。
- `sell()` 返还 `totalCost / 2` 由基类提供，子类可直接沿用。
- ⚠️ `Tower.upgrade()` / `getUpgradeCost()` / `level` / `upgradeCostBase` **已彻底删除**（原为无调用方的遗留死代码）：
  升级改走"换类原位替换"，升级费唯一来源 = `nextLevelSpec.getCost()`；
  **等级改由类身份表达**——各级塔类声明 `public static final int LEVEL`（1/2/3）并覆写 `ITowerUpgrade.getLevel()`（见 §8/§9）。

### 3. 兵营——友方出口与产出兵种

`Barrack` **未修改 `Tower` 基类**，自带一条友方出口（仿 `projectileSink` 写法）：

```java
private Consumer<Ally> allySink = a -> { };          // 默认 no-op
public void setAllySink(Consumer<Ally> sink) { ... }
protected void produce(Ally soldier) { allySink.accept(soldier); }
```

- ✅ **出口已接线**：`GameController` 放置/升级兵营时经 `injectTowerChannels` 调 `setAllySink(this::addAlly)`
  → 注入事件通道 + 进 `allies` 注册表 + 出兵音效；未注入时 no-op 丢弃、不报错。
- ✅ **产出兵种由 `createSoldier()` 钩子决定（C-3 已落地）**：
  ```java
  // Barrack（1 级，默认）
  protected Ally createSoldier() {
      return new Soldier(x, y, soldierHp, soldierSpeed, soldierAttack, soldierCooldown);
  }
  // EliteBarrack（2 级）→ new EliteSoldier(...)；MasterBarrack（3 级）→ new RoyalSoldier(...)
  ```
  **数值一个都没动**（三档仍取兵营等级字段 HP 50/80/80、伤害 8、间隔 800ms、速度 40）；
  新增兵营/兵种时**只需新增子类重写 `createSoldier()`**，不必改 `update()` 的生产流程。
- 兵营内部按 `maxSoldiers` 槽位自持在役士兵，按 `isAlive()` 剪除死亡单位，据此判定当前等级的上限（1/2/3 级 = 2/3/4）。

### 4. 跨层依赖状态

| 类 | 归属 | 状态 |
| :--- | :--- | :--- |
| `Bomb.onHit` | 实体(B) | ✅ 已实现：落点半径 ~60px 内所有存活敌人 `takeDamage` → 炮塔 AOE 溅射 |
| `Soldier.move/findTarget` | 实体(B) | ✅ 已实现（追击最近敌人 + 近战 + 回防） |
| 士兵索敌（目标锁定）"轮询" | 控制层 | ✅ 已接线（粘性锁定）：`GameController` 友方循环每帧 `a.engage(a.findTarget(enemies))` → **仅当无目标/目标已死时**写入 `Ally.target`，避免逐帧换目标抖动（`Soldier` 另有"离驻守点过远→放弃追击回防"兜底）；`Ally.pollTarget` 保留备用、**当前未接线** |

> CannonTower / Barrack 只负责"产弹 / 产兵"；炮塔 AOE 半径（~60px）由 B 在 `Bomb.onHit` 内实现，士兵拦截已通。

### 5. 新增一种塔的扩展流程

1. 在 `TowerType` 追加一个枚举常量（本文件由塔负责人维护）；
2. 新建对应 `Tower` 子类，实现 `findTarget / attack / render` 并自填数值字段；
3. 在 `Main` 里 `registerTower(type, new TowerSpec(type, "显示名", 造价), XxxTower::new)` 上架。

## 第二部分：塔升级体系

### 6. 目标与约束

- **每个等级是不同的塔**：如 `ARROW / ArrowTower`（1 级）→ `ARROW_ELITE / EliteArrowTower`（2 级，更强的箭塔）；
- **可升级对象实现一个接口**，接口能给出"更高一级塔是哪个"；
- **交互层（UI）只依赖该接口**得知升级结果（下一级名称 / 造价 / 是否满级），不 import 具体塔类、不做 instanceof 分派；
- **升级动作 = 原位"删旧塔、放新塔"**：在旧塔坐标移除旧塔，放置同一族的下一级新塔；
- 基于现有 `GameController`（单编排中枢 + 注册表 + placeTower 建塔流程）扩展，不推翻其结构。

### 7. 现状摘要（对接基线）

- `GameController`：唯一编排类，实现 `ITowerBuilder / IWaveStarter / IGameLoop / IGameStateReader`；
  持有 `GameState`、`WaveManager`、`GameConfig`、`enemies/towers/projectiles/allies` 注册表、
  `Map<TowerType, BiFunction<Double,Double,Tower>> towerFactories` 与若干通知接口；
  每帧统一驱动 + 结算，金币/生命/列表移除唯一在此；UI 全部经接口访问。
- `placeTower(x,y,type)`：越界/离路径≥30/塔间距≥40/金币校验 → `factory.apply(x,y)` →
  设坐标 → `setProjectileSink(p -> projectiles.add(p))` → `attachFx` → 加入 `towers` → 扣 `spec.cost` → 通知/重绘。
- `upgradeTower(tower)` **已改为"换类原位替换"**（不再是数值式）：校验 `ITowerUpgrade.getNextLevelSpec()` →
  取下一级工厂 → 扣 `nextSpec.getCost()` → 同坐标经工厂建新塔 → `injectTowerChannels` →
  `towers.set(idx, 新塔)` → 旧塔 `destroy()`；`Tower.upgrade()` / `getUpgradeCost()` 已删除，等级经 `ITowerUpgrade.getLevel()` 取。
  ✅ 现状：`Main` 已登记 `*_ELITE` 与 `*_MASTER` 全部升级工厂（2026-09-11）→ **L2→L3 打通，不再提示"下一级尚未开放"**。
- `TowerType` 现含 **9 个值**（`ARROW / ARROW_ELITE / ARROW_MASTER`、`CANNON / CANNON_ELITE / CANNON_MASTER`、
  `BARRACK / BARRACK_ELITE / BARRACK_MASTER`）；`Tower` 本身无类型身份/下一级查询（升级链信息在其子类/注入处）。
- `ITowerUpgrade` 纯预留 → **现已由 C 提供接口并实现**（见 §9）；`ITowerSelectionNotifier` **已有实现类**
  `view/TowerDetailPanel`，但**未经 controller 接线**（`GameController.selectionNotifier` 字段被赋值后从不被读取，
  实际由 `GameView` 直连详情面板；待定，见《整改方案》§7 P1-4）。
- 建塔菜单会把 `config.towerSpecs` 全量列出 → 升级级塔不能直接进该目录（见 §10）。

### 8. 等级模型（每级 = 独立类型 / 类）

> 数值来源：《建筑与怪物机制策划 v1.1》三级升级路线；**造价沿用 PRD（50/80/100）**；兵营出场/重生间隔取 **5s**（经确认覆盖文档的 10s）。

| 等级 | 类型枚举 | 塔类 | 说明 |
| :--- | :--- | :--- | :--- |
| 箭塔 1 级 | `ARROW` | `ArrowTower` | 可升级（实现 `ITowerUpgrade`） |
| 箭塔 2 级 | `ARROW_ELITE` | `EliteArrowTower`（继承 ArrowTower） | 可继续升级 |
| 箭塔 3 级（满级） | `ARROW_MASTER` | `MasterArrowTower`（+ `IChainShot`） | 满级，`getNextLevelSpec()` 返回 null |
| 炮塔 1 级 | `CANNON` | `CannonTower` | 可升级 |
| 炮塔 2 级 | `CANNON_ELITE` | `EliteCannonTower`（继承 CannonTower） | 可继续升级 |
| 炮塔 3 级（满级） | `CANNON_MASTER` | `MasterCannonTower`（+ `IBurnEffect`） | 满级 |
| 兵营 1 级 | `BARRACK` | `Barrack` | 可升级 |

### 9. 升级契约（C 已提供并实现）

**9.1 `ITowerUpgrade`（升级链查询）**
```java
// model/tower/ITowerUpgrade.java
public interface ITowerUpgrade {
    TowerSpec getNextLevelSpec();   // 更高一级塔目录条目；null = 已满级
    boolean isMaxLevel();
}
```
- UI 详情面板只依赖此接口，不 import 具体塔类、不做 instanceof 分派；
- 三级链（各级 `nextLevelSpec` 由塔类默认配置，`setNextLevelSpec(TowerSpec)` 供 A 覆盖）：
  - 箭塔：`ARROW` →(75) `ARROW_ELITE` →(120) `ARROW_MASTER` → 满级
  - 炮塔：`CANNON` →(150) `CANNON_ELITE` →(250) `CANNON_MASTER` → 满级
  - 兵营：`BARRACK` →(100) `BARRACK_ELITE` →(180) `BARRACK_MASTER` → 满级

**9.2 三级特殊能力接口（本次"只留接口"，效果待投射物/实体侧就绪后接入）**
```java
public interface IChainShot  { int getChainTargets(); double getChainDamageRatio(); }       // 箭塔3级：连锁箭（主目标命中后溅射 1 个，伤害 50%）
public interface IBurnEffect  { int getBurnDamagePerSecond(); int getBurnDurationMillis(); } // 炮塔3级：燃烧（每秒 5 点，持续 3 秒）
public interface IHealAura    { int getHealPerSecond(); double getAuraRadius(); }             // 兵营3级：治疗光环（周围士兵每秒 +2 血）
```
> 三个 3 级塔分别实现对应接口并返回参数；**实际效果**由投射物侧（`Arrow.onHit` 连锁）、敌人侧（DoT 燃烧）、活体侧（治疗）落地——均属 B 侧，接入时读取本接口参数即可，无需改塔类。

### 10. 目录拆分约定（重要）

- **可建造目录**（建塔菜单数据源，`IGameStateReader.getTowerSpecs()`）**只列 1 级塔**；
- 各级升级规格**不进 `config.towerSpecs` / 建塔菜单**；
- `GameController.towerFactories` 登记该族所有等级的工厂（供"原位替换"取下一级工厂用）；
- `GameConfig.addTowerSpec(...)` 只登记 1 级塔 → 避免高级塔出现在菜单。
- **注意**：现状 `registerTower(type, spec, factory)` 会内部 `addTowerSpec(spec)`，会污染菜单——为精英塔需增一条**不写目录**的纯工厂注册路径。

### 11. 原位替换流程（升级动作，交由 A 落实）

```
ITowerBuilder.upgradeTower(tower):
  1. 校验：tower 实现 ITowerUpgrade 且 getNextLevelSpec()!=null，否则提示"已满级"并返回；
  2. 扣升级费（费用语义见 §12，由实现者定义）；
  3. 取下一级 spec 与 factory → 在 tower 的 (x,y) 建新塔；
  4. 复用 placeTower 的接线：setProjectileSink(p -> projectiles.add(p)) + attachFx(新塔)；
  5. 旧塔 destroy() 并从 towers 移除；
  6. 新塔加入 towers；
  7. 通知 IStatusObserver（金币/消息）、ITowerSound.onTowerUpgraded(新塔)、requestRender()。
```
建议：把 `placeTower` 内部抽成 `private Tower buildTowerAt(double x,double y,TowerType type, boolean deduct)`，建塔与升级共用，保证接线一致。
