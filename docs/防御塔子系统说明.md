# 防御塔子系统说明

> 归属：防御塔开发（角色 C）
> 供架构 A / 实体 B / UI D 对照。
> **数值口径**：塔与士兵的一切可调数值以 `config/tower.json` 为准，溅射半径以 `config/balance.json` 为准——
> 本文档只列**键名与语义**，不抄写具体数字（完整归属见《数值配置 JSON 化规范》§0/§2.3）。

## 第一部分：塔参数与契约

### 1. 三种防御塔一览

| 塔 | 类型枚举 | 1 级塔类 | 数值键前缀（`config/tower.json`） | 机制 |
| :--- | :--- | :--- | :--- | :--- |
| 箭塔 | `ARROW` | `ArrowTower` | `arrowL1` | 单体，追踪 `Arrow` |
| 炮塔 | `CANNON` | `CannonTower` | `cannonL1` | 群攻，定点 `Bomb`，溅射半径见 `balance.json` 的 `cannonSplashRadius` |
| 兵营 | `BARRACK` | `Barrack` | `barrackL1` | 生产士兵拦截敌人（1/2/3 级分别产 `Soldier` / `EliteSoldier` / `RoyalSoldier`） |

- **塔数值键**：每一级一个 id（`arrowL1/L2/L3`、`cannonL1/L2/L3`、`barrackL1/L2/L3`），字段含义见 §14 与《数值配置 JSON 化规范》§2.3。
- **造价**不在 JSON 内，仍是塔类常量 `BUILD_COST` / `UPGRADE_COST`，由 `Main` 登记进 `TowerSpec`。
- **兵营生产语义**：维护 `maxSoldiers` 个槽位，**每槽位各带独立补位计时器**；士兵阵亡后该槽位独立重新计时 `spawnIntervalMs` 再补位（不是「死亡立即复活」），其它槽位不受影响；初始错峰产出（0 / 间隔 / 2×间隔 …）；眩晕时暂停生产。

### 2. 共同契约（继承 `Tower` 基类）

- 子类须实现 `findTarget(List<Enemy>)`、`attack(Enemy)`、`render(GraphicsContext)`。
- 数值字段（`attackRange / attackCooldown / baseAttackDamage / totalCost`）在构造函数内填充，**来源为 `TowerBalance.getInt/getDouble(塔 id, 字段, 兜底值)`**（见《数值配置 JSON 化规范》§2.3）。
- **`totalCost` 必须播种造价**，否则 `sell()` 返还恒为 0。
- 发射统一走 `fire(Projectile)` → `projectileSink`（GameController 在 `placeTower` 接入）。
- `sell()` 返还 `totalCost / 2` 由基类提供，子类可直接沿用。
- `Tower.upgrade()` / `getUpgradeCost()` / `level` / `upgradeCostBase` **已彻底删除**（原为无调用方的遗留死代码）：升级改走「换类原位替换」，升级费唯一来源 = `nextLevelSpec.getCost()`；**等级由类身份表达**——各级塔类声明 `public static final int LEVEL`（1/2/3）并覆写 `ITowerUpgrade.getLevel()`。

### 3. 兵营——友方出口与产出兵种

`Barrack` **未修改 `Tower` 基类**，自带一条友方出口（仿 `projectileSink` 写法）：

```java
private Consumer<Ally> allySink = a -> { };          // 默认 no-op
public void setAllySink(Consumer<Ally> sink) { ... }
protected void produce(Ally soldier) { allySink.accept(soldier); }
```

- **出口已接线**：`GameController` 放置/升级兵营时经 `injectTowerChannels` 调 `setAllySink(this::addAlly)` → 注入事件通道 + 进 `allies` 注册表 + 出兵音效；未注入时 no-op 丢弃、不报错。
- **产出兵种由 `createSoldier()` 钩子决定**：
  ```java
  // Barrack（1 级，默认）
  protected Ally createSoldier() {
      return new Soldier(x, y, soldierHp, soldierSpeed, soldierAttack, soldierCooldown);
  }
  // EliteBarrack（2 级）→ new EliteSoldier(...)；MasterBarrack（3 级）→ new RoyalSoldier(...)
  ```
  三档士兵的 HP / 速度 / 攻击 / 冷却**全部取本兵营等级字段**（构造期由 `barrackL*` 键读入）；新增兵营/兵种时**只需新增子类重写 `createSoldier()`**，不必改 `update()` 的生产流程。
- **旧兵交接**：
  ```java
  public List<Ally> getSoldiers()      // 在役士兵只读快照（副本，不影响槽位）
  public List<Ally> releaseSoldiers()  // 交出全部在役士兵并清空本兵营槽位记录
  ```
  `GameController` 在**升级原位替换前**与**出售后**各调用一次：升级时移除旧兵（避免新旧两批并存），出售时一并清退。
  `releaseSoldiers()` 只清**兵营侧**槽位记录，**不动 `allies` 注册表**（注册表归 GameController）；清槽后若该兵营继续存在，会按初始错峰节奏重新补位。

### 4. 跨层依赖状态

| 类 | 归属 | 状态 |
| :--- | :--- | :--- |
| `Bomb.onHit` | 实体(B) | 已实现：落点半径内所有存活敌人 `takeDamage` → 炮塔 AOE 溅射；半径**由构造参数传入**，各级炮塔构造期从 `balance.json` 的三个 `*CannonSplashRadius` 键取值后传入，`Bomb` 内**无**硬编码半径 |
| `Soldier.move/findTarget` | 实体(B) | 已实现（追击最近敌人 + 近战 + 回防） |
| 士兵索敌（目标锁定） | 控制层 | 已接线（**粘性锁定**）：`GameController` 友方循环每帧 `a.engage(a.findTarget(enemies))` → 仅当无目标/目标已死时写入 `Ally.target`，避免逐帧换目标抖动（`Soldier` 另有「离驻守点过远 → 放弃追击回防」兜底）；`Ally.pollTarget` 保留备用、**当前未接线** |

### 5. 新增一种塔的扩展流程

1. 在 `TowerType` 追加一个枚举常量；
2. 新建对应 `Tower` 子类，实现 `findTarget / attack / render`，构造期经 `TowerBalance` 读数值字段；
3. 在 `Main` 里 `registerTower(type, new TowerSpec(type, "显示名", 造价), XxxTower::new)` 上架（升级级另用 `registerUpgradeFactory`，见 §9）。

## 第二部分：塔升级体系

### 6. 目标与约束

- **每个等级是不同的塔**：`ARROW/ArrowTower`（1 级）→ `ARROW_ELITE/EliteArrowTower`（2 级）→ `ARROW_MASTER/MasterArrowTower`（3 级）；
- **可升级对象实现一个接口**，接口能给出「更高一级塔是哪个」；
- **UI 只依赖该接口**得知升级结果（下一级名称 / 造价 / 是否满级），不 import 具体塔类、不做 instanceof 分派；
- **升级动作 = 原位「删旧塔、放新塔」**：在旧塔坐标移除旧塔，放置同一族的下一级新塔；
- 基于现有 `GameController`（单编排中枢 + 注册表 + `placeTower` 建塔流程）扩展，不推翻其结构。

### 7. 现状摘要（对接基线）

- `GameController`：唯一编排类，实现 `ITowerBuilder / IWaveStarter / IGameLoop / IGameStateReader / ILevelSwitcher`；持有 `GameState`、`WaveManager`、`GameConfig`、`enemies/towers/projectiles/allies` 注册表、`Map<TowerType, BiFunction<Double,Double,Tower>> towerFactories` 与若干通知接口；每帧统一驱动 + 结算，金币/生命/列表移除唯一在此；UI 全部经接口访问。
- `placeTower(x, y, type)`：越界 / 离路径过近 / 塔间距过近 / 金币校验 → `factory.apply(x,y)` → 设坐标 → `setProjectileSink(p -> projectiles.add(p))` → 注事件通道 → 加入 `towers` → 扣 `spec.cost` → 通知/重绘。
- `upgradeTower(tower)` 为**换类原位替换**：校验 `ITowerUpgrade.getNextLevelSpec()` → 取下一级工厂 → 扣 `nextSpec.getCost()` → 同坐标经工厂建新塔 → `injectTowerChannels` → 替换列表中旧塔 → 旧塔 `destroy()`；兵营另先 `releaseSoldiers()`。
- `TowerType` 含 **9 个值**；`Tower` 本身无类型身份/下一级查询（升级链信息在其子类/注入处）。
- `ITowerSelectionNotifier` 已有实现类 `view/TowerDetailPanel`，但**未经 controller 接线**（`GameController.selectionNotifier` 赋值后从不被读取，实际由 `GameView` 直连详情面板）。
- 建塔菜单会把 `towerSpecs` 全量列出 → 升级级塔不能直接进该目录（见 §9）。

### 8. 等级模型（每级 = 独立类型 / 类）

| 等级 | 类型枚举 | 塔类 | 数值键 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 箭塔 1 级 | `ARROW` | `ArrowTower` | `arrowL1` | 可升级（实现 `ITowerUpgrade`） |
| 箭塔 2 级 | `ARROW_ELITE` | `EliteArrowTower`（继承 ArrowTower） | `arrowL2` | 可继续升级 |
| 箭塔 3 级（满级） | `ARROW_MASTER` | `MasterArrowTower`（+ `IChainShot`） | `arrowL3` | `getNextLevelSpec()` 返回 null |
| 炮塔 1 级 | `CANNON` | `CannonTower` | `cannonL1` | 可升级 |
| 炮塔 2 级 | `CANNON_ELITE` | `EliteCannonTower`（继承 CannonTower） | `cannonL2` | 可继续升级 |
| 炮塔 3 级（满级） | `CANNON_MASTER` | `MasterCannonTower`（+ `IBurnEffect`） | `cannonL3` | 满级 |
| 兵营 1 级 | `BARRACK` | `Barrack` | `barrackL1` | 可升级 |
| 兵营 2 级 | `BARRACK_ELITE` | `EliteBarrack`（继承 Barrack） | `barrackL2` | 可继续升级 |
| 兵营 3 级（满级） | `BARRACK_MASTER` | `MasterBarrack`（+ `IHealAura`） | `barrackL3` | 满级 |

### 9. 升级契约

**9.1 `ITowerUpgrade`（升级链查询）**
```java
// model/tower/ITowerUpgrade.java
public interface ITowerUpgrade {
    TowerSpec getNextLevelSpec();   // 更高一级塔目录条目；null = 已满级
    boolean isMaxLevel();
    int getLevel();                 // 本塔等级（由类身份决定：1/2/3）
}
```
- UI 详情面板只依赖此接口，不 import 具体塔类、不做 instanceof 分派；
- 三级链（各级 `nextLevelSpec` 由塔类默认配置，`setNextLevelSpec(TowerSpec)` 供装配层覆盖）：
  - 箭塔 `ARROW` → `ARROW_ELITE` → `ARROW_MASTER` → 满级
  - 炮塔 `CANNON` → `CANNON_ELITE` → `CANNON_MASTER` → 满级
  - 兵营 `BARRACK` → `BARRACK_ELITE` → `BARRACK_MASTER` → 满级
  （每级的**升级费**是其目标级 `TowerSpec.cost`，即塔类 `UPGRADE_COST` 常量。）

**9.2 三级特殊能力接口**
```java
public interface IChainShot  { int getChainTargets(); double getChainDamageRatio(); }        // 箭塔3级：连锁箭
public interface IBurnEffect  { int getBurnDamagePerSecond(); int getBurnDurationMillis(); }  // 炮塔3级：燃烧 DoT
public interface IHealAura    { int getHealPerSecond(); double getAuraRadius(); }              // 兵营3级：治疗光环
```
- 参数分别取 `config/tower.json` 的 `arrowL3.chainTargets/chainDamageRatio`、`cannonL3.burnDps/burnDurationMs`、`barrackL3.healPerSecond/auraRadius`；
- **实际效果**由投射物侧（`Arrow.onHit` 连锁）、敌人侧（DoT 燃烧）、活体侧（治疗）落地——均属 B 侧，接入时读取本接口参数即可，**无需改塔类**。

### 10. 目录拆分与注册路径

- **可建造目录**（建塔菜单数据源，`IGameStateReader.getTowerSpecs()`）**只列 1 级塔**；
- 各级升级规格**不进 `towerSpecs` / 建塔菜单**；
- `GameController.towerFactories` 登记该族所有等级的工厂（供「原位替换」取下一级工厂用）；
- 两条注册路径：`registerTower(type, spec, factory)` = 进目录（建塔菜单）+ 记工厂；`registerUpgradeFactory(type, factory)` = **只记工厂、不写目录**——升级级必须走后者，否则会污染菜单。

### 11. 原位替换流程（升级动作）

```
ITowerBuilder.upgradeTower(tower):
  1. 校验：tower 实现 ITowerUpgrade 且 getNextLevelSpec() != null，否则提示「已满级」并返回；
  2. 扣升级费 = nextSpec.getCost()；
  3. 取下一级 spec 与 factory → 在 tower 的 (x,y) 建新塔；
  4. 复用 placeTower 的接线：setProjectileSink(...) + 注事件通道（injectTowerChannels）；
  5. 兵营：旧塔 releaseSoldiers() 并移除旧兵；旧塔 destroy() 并从 towers 移除；
  6. 新塔加入 towers；
  7. 扣费/消息通知 IStatusObserver → ITowerSound.onTowerUpgraded(新塔) → requestRender()。
```

### 12. 费用与退款

| 项 | 语义 |
| --- | --- |
| 升级价 | 取下一级 `TowerSpec.getCost()`（即目标级塔类的 `UPGRADE_COST` 常量）；`GameController.upgradeTower` 扣此值 |
| totalCost 累计 | 各级塔构造函数内置为本级累计投入（L1 造价 → +L2 升级费 → +L3 升级费），供出售退款计算 |
| 出售退款 | `tower.sell() = totalCost / 2`（详情面板显示 `getTotalCost() / 2`） |
| 通知 | 升级成功走 `ITowerSound.onTowerUpgraded`（参数为新塔） |

### 13. UI 接入

- 详情面板拿到选中 `Tower` 后，**只经 `ITowerUpgrade`**：
  - `getNextLevelSpec()` 非 null → 显示「升级为 <显示名> (<造价>)」按钮；
  - `isMaxLevel()` → 隐藏/置灰升级按钮；
  - 点击调用 `ITowerBuilder.upgradeTower(tower)`；
- 全程不 import 具体塔类。
- ⚠️ `TowerDetailPanel` 刻意不 import 具体塔类，因此**不展示**溅射半径等分族特例信息；`CannonTower.getSplashRadius()` / `Bomb.getSplashRadius()` 目前无 UI 调用方。

### 14. 数值键一览（正文不抄数值，改数值请改 `config/tower.json`）

| 塔 id | 字段 |
| :--- | :--- |
| `arrowL1` / `arrowL2` / `arrowL3` | `damage` / `range` / `cooldownMs`；L3 另有 `chainTargets` / `chainDamageRatio` |
| `cannonL1` / `cannonL2` / `cannonL3` | `damage` / `range` / `cooldownMs`；L3 另有 `burnDps` / `burnDurationMs` |
| `barrackL1` / `barrackL2` / `barrackL3` | `maxSoldiers` / `spawnIntervalMs` / `soldierHp` / `soldierSpeed` / `soldierAttack` / `soldierCooldown`；L3 另有 `healPerSecond` / `auraRadius` |

- 炮塔**溅射半径**不在本表：见 `config/balance.json` 的 `cannonSplashRadius` / `eliteCannonSplashRadius` / `masterCannonSplashRadius`。
- 士兵**分级类**为三档并列（`Soldier` / `EliteSoldier` / `RoyalSoldier`，均直接继承 `Ally`，见《友方士兵子系统说明》），数值取所属兵营等级的 `soldier*` 字段。
