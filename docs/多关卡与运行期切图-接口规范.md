## 0. 定位与术语

### 0.1 定位

本文档回答三件事：

1. **数据长什么样**——关卡（地图）如何注册、如何排序、目录如何组织（§2）；
2. **接口叫什么**——读关卡个数/名字、查询当前关、跳转/切关的**方法签名与失败行为**（§3）；
3. **不变量是什么**——切换成功后哪些状态被重置、哪些必须保持不变（§3.4、§5）。

> 本文档是**契约**：实现方（A）与消费方（D/UI）以此为准；实现细节（如抽取哪个私有方法）不属于契约。

### 0.2 术语

| 术语 | 含义 |
| :--- | :--- |
| **关卡** | **一张地图**，由 `maps/index.json` 中的一个 `key` 唯一标识（本方案：一关一张图） |
| **关卡序号** | 该关在 `index.json` 数组中的下标，**从 0 起**；顺序即关卡顺序 |
| **当前关卡** | 当前正在游玩的地图（`GameConfig.getMapKey()`） |
| **切图 / 切关** | 运行期把"当前关卡"换成另一张地图，**不重启 JVM** |
| **地图域数据** | `mapKey` / `mapImageName` / `pathX,pathY` / `towerSpots` / `levelWaves` / `totalWaves` |
| **全局域数据** | `balance.json` 数值（开局金币/生命、敌人属性、塔属性…）——**与关卡无关** |

### 0.3 相关方

| 代号 | 职责 |
| :--- | :--- |
| **A** | 契约本身、`GameConfig` / `GameState` / `GameController` 的实现 |
| **D** | UI 消费：选关/下一关入口、切换后的界面清理 |
| **E** | 地图资源（`maps/` 目录与 `index.json` 登记） |
| **F** | 验收（§7） |

## 1. 目标与范围

### 1.1 目标

- 游戏运行中，可在**不重启进程**的前提下切换到另一关卡；
- 提供"读取关卡个数与名字、查询当前关、按 key/序号跳转、上一关/下一关、重开本关"的完整接口；
- 切换后地图几何（路径/塔位）、底图、波次表、胜负判定口径**全部随新关生效**。

### 1.2 范围外（本版明确不做）

| 不做项 | 原因 / 现状 |
| :--- | :--- |
| 热重载 `balance.json`（数值） | `BalanceTable.runtime()` 为一次性缓存单例，**改文件需重启**（`BalanceTable.java:485` 已有明文约定） |
| 热重载贴图 / 尺寸 / 动画 | `Assets`、`SizeTable.getInstance()`、`AnimTable` 均为一次性缓存，无失效入口 |
| **同一 key** 改 `waves.json` 后热更新 | `LevelWaves.CACHE` 按**资源路径**永久缓存（`LevelWaves.java:65`）；切到**不同 key** 正常，改同 key 需重启 |
| 不同尺寸地图的动态 canvas 缩放 | `GameView` canvas 在构造期固定（`GameView.java:197`）。**MVP 要求各关卡地图同尺寸** |
| 存档 / 关卡解锁进度 | 后续需求，另行设计 |

## 2. 数据契约（E 域）

### 2.1 注册表 `maps/index.json`

**现状结构**（`MapLibrary.MapEntry` 仅支持这三个字段，`MapLibrary.java:39-65`）：

```json
{
  "maps": [
    { "key": "default", "name": "默认地图", "image": "map.png" }
  ]
}
```

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `key` | ✅ | 关卡唯一标识，同时是目录名 |
| `name` | ➖ | 显示名；缺省回退 `key`（`MapEntry.java:46`） |
| `image` | ➖ | 底图文件名；缺省回退 `"map.png"`（`:47`） |

**关卡顺序 = `index.json` 数组顺序**（`listMapsFromClasspath()` 按数组顺序解析）。

> 🔧 **可选扩展（本版不实现，留占位）**：若将来需要显式排序/章节，可在条目追加 `"order": 1`，届时 `MapEntry` 增 `getOrder()`，排序以 `order` 升序、缺省取下标。

### 2.2 每关目录结构

```
src/main/resources/maps/
├── index.json                 关卡注册表（顺序事实源）
└── <key>/
    ├── <image>                底图（默认 map.png）
    ├── path.json              敌人路径（MapRoute 结构）
    ├── spots.json             塔位（TowerSpots 结构）
    └── waves.json             波次表（LevelWaves 结构，含该关波数）
```

### 2.3 新增一个关卡的流程

1. 在 `maps/` 下新建目录 `<key>/`，放入底图、`path.json`、`spots.json`、`waves.json`；
2. 在 `index.json` 的 `maps` 数组中**按期望的关卡顺序**追加 `{ "key", "name", "image" }`；
3. 重启游戏验证（`index.json` 为运行期只读，走 classpath）。

### 2.4 每关差异边界（**重要**）

| 数据 | 是否随关卡变化 | 来源 |
| :--- | :--- | :--- |
| 地图几何（路径、塔位）、底图 | ✅ **每关不同** | `maps/<key>/*` |
| 波次组合、**该关总波数** | ✅ **每关不同** | `maps/<key>/waves.json`（波数唯一来源，见《整改方案》§5 裁定） |
| 开局金币 / 开局生命 | ❌ **全局值**，不随关卡变化 | `config/balance.json`（`initialGold` / `initialLives`） |
| 敌人 / 塔 / 投射物属性 | ❌ 全局值 | `config/balance.json` |

> ⚠️ 因此"切关后金币/生命回到**该关**初值"在当前数据模型下等价于"回到**全局**初值"。
> 若将来要**按关配置**开局金币/生命，属可选扩展：建议在 `maps/<key>/` 内新增关卡级配置（或扩展 `waves.json` 头部），**不在本版范围**。

## 3. 接口规范（核心）

> 分层原则：**UI 只依赖 `GameController` 暴露的关卡 API**，不得直接引用 `GameConfig` / `MapLibrary`（对齐《接口契约》"UI 只经接口"）。

### 3.1 `LevelInfo`（新增值对象，A 域）

用于关卡列表的只读展示，**不可变**。

```java
public final class LevelInfo {
    public int    getIndex();   // 关卡序号，从 0 起；= index.json 数组下标
    public String getKey();     // 关卡 key（= 地图 key）
    public String getName();    // 显示名（index.json 的 name，缺省回退 key）
}
```

### 3.2 `GameConfig`（A 域）

```java
/** 重载"地图域"数据到本实例；成功 true，失败 false（且不改变当前状态）。 */
public boolean loadMap(String key);

public String getMapKey();          // 已有（GameConfig.java:189）
public String getMapDisplayName();  // 新增：读 index.json 中该 key 的 name
public int    getTotalWaves();      // 已有（:206）：随地图刷新（waves.json 决定）
```

**`loadMap(key)` 契约（严格）**：

| 项 | 约定 |
| :--- | :--- |
| 影响的字段 | 仅**地图域**：`mapKey` / `mapImageName` / `pathX,pathY` / `towerSpots` / `levelWaves` / `totalWaves` |
| **不得**影响 | 全局域：`initialGold` / `initialLives` / 敌人与塔的数值（来自 `balance.json`） |
| 原子性 | 先读到局部变量，**全部成功**才写回实例字段；任一步失败 → 返回 `false`，**原地图数据保持不变** |
| 失败条件 | `key` 不在 `index.json`；`path.json` / `spots.json` 缺失或解析失败 |
| 波次缺失 | 沿用构造器既有口径：回退全局波次配置并告警（不视为失败） |
| 线程 | 仅游戏线程调用（与 `resetGame` 同线程约定） |

### 3.3 `GameController`（对 UI 的唯一入口，A 域）

```java
// —— 关卡列表与查询 ——
List<LevelInfo> getLevels();          // 全部关卡，顺序即关卡顺序
int             getLevelCount();      // 关卡总数
LevelInfo       getCurrentLevel();    // 当前关卡信息（含序号与名字）
String          getCurrentLevelKey(); // 当前关卡 key
int             getCurrentLevelIndex(); // 当前关卡序号（未匹配到返回 -1）

// —— 跳转与切关 ——
boolean switchLevel(String key);      // 跳转到指定关卡
boolean switchLevelAt(int index);     // 按序号跳转（越界 → false）
boolean hasNextLevel();               // 是否还有下一关
boolean hasPrevLevel();               // 是否有上一关
boolean goNextLevel();                // 下一关（无则 false）
boolean goPrevLevel();                // 上一关（无则 false）

// —— 重开 ——
boolean restartLevel();               // 重开本关（不切图）
```

**返回值语义**：`boolean` 一律表示**动作是否发生**；`false` 时**状态零变化**，并应给出用户可见提示（`notifyMessage`）。

### 3.4 状态语义与不变量（**必须遵守**）

| 事件 | 金币 / 生命 | 波次进度 | 场上实体（敌/塔/兵/弹） | 底图 / 路径 / 塔位 |
| :--- | :--- | :--- | :--- | :--- |
| `switchLevel` / `switchLevelAt` / `goNextLevel` / `goPrevLevel` **成功** | 重置为初值 | 归零（回到未开战） | **全部清空** | **换为新关** |
| 同上 **失败**（非法 key / 越界） | 不变 | 不变 | 不变 | **不变** |
| `restartLevel` | 重置为初值 | 归零 | 全部清空 | **不变**（同关重开） |

补充约定：

- 切关**不得**修改全局数值（`balance.json` 链）；
- 切关后 `getTotalWaves()` 必须等于新关 `waves.json` 的波数（胜负判定随之更新）；
- 切关后"下一波倒计时"等波次节奏被复位（未开战状态）。

### 3.5 UI 契约（D 域消费约定）

1. 只调用 §3.3 的 `GameController` 方法；**不得**直接读 `GameConfig` / `MapLibrary`；
2. 切关成功后需清理**选中态**（详情面板）与**瞬态特效**（飘字/粒子/闪屏）——可直接复用 `GameView` 现有的 `clearTransientEffects()` 先例（`GameView.java:528-532`）；
3. "下一关 / 上一关"按钮在 `hasNextLevel()` / `hasPrevLevel()` 为 `false` 时**置灰或隐藏**；
4. 波次进行中触发切关时，建议先弹二次确认（切关会清空战场）。

## 4. 时序

### 4.1 启动时序（现状 + 本方案改动）

```
Main.start()
  └─ new GameConfig()
        ├─ 读 /config/balance.json              → 全局域
        └─ 地图域加载（本方案抽出为 loadMap）
              ├─ MapLibrary.listMapsFromClasspath()   读 maps/index.json
              ├─ System.getProperty("map.key")        启动参数覆盖默认
              └─ readPath/Spots/WavesFromClasspath(key)
  ├─ new GameState(config)      ← 缓存 initialGold/initialLives/totalWaves
  ├─ new WaveManager()
  ├─ new GameController(state, waveManager, config)
  └─ new GameView(controller, …, config, …, controller::resetGame)
```

### 4.2 切换关卡时序

```
UI（D）
 │  用户点"下一关" / 选关
 ▼
GameController.switchLevel(key)
 ├─ config.loadMap(key)                     ← 失败：notifyMessage 并 return false（状态零变化）
 ├─ clearBattlefield()                      ← 清 enemies / towers / projectiles / allies
 │                                            + waveManager.reset() + 复位波次节奏标志
 ├─ state.applyConfig(config)               ← 金币/生命/总波数按新 config 重置
 ├─ notifyGold / notifyLives / notifyMessage
 └─ requestRender()
        │
        ▼
 GameView.draw() 每帧自检：
   config.getMapKey() != 上一帧的 key  →  loadMapBackground()（底图换新）
   （路径/塔位点无需处理：GameView 每帧现读 config.getPathX()/getTowerSpots()）
```

> **设计要点**：`GameView` 的路径与塔位点是**每帧现读** `config`（`GameView.java:277-278,359,378,402,428,500,594`），只有底图被缓存 → 因此底图"自检重载"即可，**无需新增任何接口/回调**。

## 5. 错误与边界

| 场景 | 约定行为 |
| :--- | :--- |
| `switchLevel` 传入未知 `key` | 返回 `false`；提示"关卡不存在"；**保持原关** |
| `switchLevelAt` 传入越界序号 | 返回 `false`；同上 |
| 目标关 `path.json` / `spots.json` 缺失或损坏 | `loadMap` 返回 `false`；保持原关 |
| 目标关 `waves.json` 缺失 | 沿用既有口径：回退全局波次配置 + 告警；切关**仍成功** |
| `index.json` 为空 | `getLevels()` 返回空列表，`getLevelCount()==0`；切关一律 `false` |
| 波次进行中切关 | **直接清空战场**（按 §3.4）；UI 建议二次确认 |
| 各关地图尺寸不同 | **本版不支持**：canvas 构造期固定（`GameView.java:197`），要求同尺寸 |

**缓存边界（不改，但必须知道）**：
- 切到**不同 key** 不受缓存影响（缓存以资源路径为键）；
- **同一 key** 修改 `waves.json` 后**不会生效**，需重启；
- `balance.json` / `sizes.json` / `Assets` / `AnimTable` 均**不可热重载**。

## 7. 验收（Definition of Done）

1. **接口齐备**：§3.3 所有方法存在且可编译，签名与文档一致；
2. **运行期切图**：游戏中调用 `switchLevel(otherKey)` → 底图、路径、塔位点、波次表全部换为新关；金币/生命回到初值；波次归零；场上实体清空；**进程未重启、无异常**；
3. **失败零副作用**：传入非法 key → 返回 `false`，且地图/状态/实体**与调用前完全一致**；
4. **胜负口径随关**：切关并打完一轮后，胜/负判定按**新关** `totalWaves`；
5. **不改全局**：切关前后 `balance.json` 相关数值（金币/生命初值、敌人与塔属性）不变；
6. **编译**：全量 `javac` 0 error；
7. **最小手工用例**：
   ```
   ① 启动（默认关）→ 记录底图/路径/总波数
   ② 调 goNextLevel()（或 switchLevel("<某关>"））
   ③ 断言：底图与路径变为新关、总波数变为新关值、金币/生命回到初值、场上无残留实体
   ④ 调 switchLevel("__不存在__") → 断言 false 且一切未变
   ⑤ 调 restartLevel() → 断言金币/生命/波次重置、地图未变
   ```
